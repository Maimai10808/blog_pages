# 一文理解 TCP/IP 模型与 OSI 模型：为什么网络设备能互相通信？

## 1. 为什么需要网络模型？

今天我们已经习惯了不同设备之间互相通信。

比如：

- iPhone 可以访问网站；
- Windows 电脑可以给 Mac 电脑传文件；
- 树莓派可以和手机在同一个网络中通信；
- 浏览器可以访问全球各地的服务器；
- 手机 App 可以请求后端接口。

这些事情现在看起来很普通，但在早期计算机网络刚出现时，并不是理所当然的。

过去，不同厂商的计算机和网络设备往往使用各自私有的通信方式。IBM 有自己的网络方案，其他公司也有自己的网络方案。结果就是：同一个厂商内部的设备可能能通信，但不同厂商之间的设备很难互相通信。

它们就像在说不同语言：

```text id="0d5mmt"
A 网络：Bonjour
B 网络：What?
```http

如果没有统一标准，不同设备之间就无法顺畅协作。于是，人们开始意识到：必须制定一套通用的网络规则，让所有厂商按照同一套标准来设计设备和协议。

这就是网络模型出现的原因。

网络模型的核心价值是：

> 把复杂的网络通信过程拆分成多个层次，每一层负责不同功能，并通过统一标准让不同设备能够互相通信。

## 2. 互联网的早期背景：从 ARPANET 开始

现代互联网的雏形可以追溯到 20 世纪 60 年代。

1969 年，美国国防部推动了 ARPANET 的建设。ARPANET 被认为是互联网发展的重要起点。它实现了让多台计算机通过网络互相通信的目标，也推动了分组交换技术的发展。

分组交换的基本思想是：

> 数据不会整块一次性传输，而是被拆分成多个小的数据包，在网络中分别传输，最后再由接收方重新组合。

这也是现代网络通信的基础思想之一。

不过，早期网络虽然已经有了“让计算机互联”的想法，但还没有形成统一、成熟、被广泛接受的标准。各个厂商仍然可能自己设计自己的网络体系。

所以，后来就需要一种更通用的模型，来规范不同系统之间如何通信。

## 3. 什么是 TCP/IP 模型？

TCP/IP 模型是今天互联网真正广泛使用的网络模型。

它也常被称为 **TCP/IP 协议栈**。

所谓协议栈，可以理解为一组分层协议的集合。每一层负责不同的网络功能，多层协议配合起来，最终完成一次完整的网络通信。

TCP/IP 模型常见可以分为四层或五层。在学习 CCNA 或实际网络工程时，经常使用五层结构来理解：

| 层级    | 名称       | 主要功能                        |
| ------- | ---------- | ------------------------------- |
| 第 5 层 | 应用层     | HTTP、DNS、FTP、SMTP 等应用协议 |
| 第 4 层 | 传输层     | TCP、UDP、端口号                |
| 第 3 层 | 网络层     | IP 地址、路由                   |
| 第 2 层 | 数据链路层 | MAC 地址、交换机、帧            |
| 第 1 层 | 物理层     | 网线、电信号、光信号、网卡接口  |

TCP/IP 模型之所以重要，是因为今天几乎所有联网设备都在使用它。无论是电脑、手机、服务器、路由器，还是物联网设备，它们能够互相通信，都是因为遵循了这套通用协议体系。

## 4. TCP/IP 各层分别做什么？

## 4.1 物理层：真正传输信号

物理层关注的是最底层的信号传输。

它涉及：

- 网线；
- 光纤；
- 无线电波；
- 网卡；
- 接口；
- 电信号；
- 光信号。

比如一根以太网线连接电脑和交换机时，数据最终会以电信号的方式在网线中传输。这部分就属于物理层。

物理层并不关心 IP 地址、网页内容、应用程序，它只负责把比特流传出去。

可以简单理解为：

> 物理层负责“信号怎么走”。

## 4.2 数据链路层：同一网络内怎么通信

数据链路层主要解决同一个局域网内设备之间如何通信的问题。

这一层最重要的地址是 **MAC 地址**。

MAC 地址通常被称为二层地址。交换机主要工作在数据链路层，它会根据 MAC 地址决定把数据帧转发到哪个端口。

例如，同一个局域网中的电脑 A 想把数据发给电脑 B，交换机会查看目标 MAC 地址，然后把数据转发到对应端口。

这一层涉及的典型设备是：

- 交换机；
- 网桥；
- 无线接入点的一部分功能。

可以简单理解为：

> 数据链路层负责“同一个网络里找谁”。

## 4.3 网络层：跨网络怎么通信

网络层主要负责跨网络通信。

这一层最重要的地址是 **IP 地址**。

当两台设备不在同一个局域网中时，就需要通过路由器进行转发。路由器根据目标 IP 地址判断下一跳应该往哪里走。

例如，你在家访问一个国外网站，你的请求不会只在家庭局域网中转发，而是会经过路由器、运营商网络、骨干网络，最终到达目标服务器。

这就是网络层要解决的问题。

网络层的核心内容包括：

- IP 地址；
- 子网；
- 路由；
- 路由器；
- 数据包转发。

可以简单理解为：

> 网络层负责“跨网络找目的地”。

## 4.4 传输层：数据怎么可靠传输

传输层负责端到端的数据传输。

这一层最常见的协议是：

- TCP；
- UDP。

TCP 提供可靠传输。它会处理连接建立、数据确认、重传、排序、流量控制等问题。HTTP/1.1 和 HTTP/2 通常运行在 TCP 之上。

UDP 则更简单，不保证可靠传输，但延迟低、开销小，常用于视频、语音、游戏、DNS、QUIC 等场景。

传输层还有一个非常重要的概念：**端口号**。

IP 地址可以定位一台主机，端口号则可以定位这台主机上的某个应用程序。

例如：

```text id="3wc4od"
192.168.1.10:80
192.168.1.10:443
192.168.1.10:3306
```

同一台服务器上可能同时运行 Web 服务、数据库服务、SSH 服务，它们就通过不同端口区分。

可以简单理解为：

> 网络层负责找到哪台机器，传输层负责找到机器上的哪个程序。

## 4.5 应用层：应用程序使用的协议

应用层直接面向应用程序。

常见应用层协议包括：

| 协议         | 作用               |
| ------------ | ------------------ |
| HTTP / HTTPS | 网页访问、接口请求 |
| DNS          | 域名解析           |
| FTP          | 文件传输           |
| SMTP         | 邮件发送           |
| POP3 / IMAP  | 邮件接收           |
| SSH          | 远程登录           |

比如你在浏览器中访问一个网站，本质上就是浏览器使用 HTTP 或 HTTPS 协议和服务器通信。

应用层解决的是：

> 应用程序之间应该用什么格式、什么规则来交换数据。

## 5. 什么是 OSI 模型？

OSI 模型，全称是 **Open Systems Interconnection Model，开放式系统互联模型**。

它也是一种网络分层模型，但它分得更细，一共有七层：

| 层级    | 名称       |
| ------- | ---------- |
| 第 7 层 | 应用层     |
| 第 6 层 | 表示层     |
| 第 5 层 | 会话层     |
| 第 4 层 | 传输层     |
| 第 3 层 | 网络层     |
| 第 2 层 | 数据链路层 |
| 第 1 层 | 物理层     |

OSI 模型在实际互联网中并没有像 TCP/IP 那样成为真正主导的实现模型，但它在网络学习、考试和故障排查中非常重要。

网络工程师经常会说：

- 这是 Layer 1 问题；
- 这是 Layer 2 问题；
- 这是 Layer 3 问题；
- 这是 Layer 7 问题。

这里说的 Layer，通常就是按 OSI 模型来表达的。

## 6. OSI 七层分别是什么？

## 6.1 第 1 层：物理层

物理层负责传输原始比特流。

相关内容包括：

- 网线；
- 光纤；
- 电信号；
- 无线信号；
- 接口标准；
- 集线器；
- 中继器。

典型设备：

- Hub，集线器；
- Repeater，中继器。

Hub 和 Repeater 都比较“低级”，它们不理解 MAC 地址，也不理解 IP 地址，只负责转发或放大信号。

## 6.2 第 2 层：数据链路层

数据链路层负责同一局域网内的数据传输。

核心概念：

- MAC 地址；
- 数据帧；
- 交换机；
- 网桥；
- VLAN。

典型设备：

- Switch，交换机；
- Bridge，网桥。

交换机主要工作在二层，它根据 MAC 地址转发数据帧。

## 6.3 第 3 层：网络层

网络层负责跨网络通信。

核心概念：

- IP 地址；
- 路由；
- 子网；
- 数据包；
- 路由器。

典型设备：

- Router，路由器；
- 三层交换机。

路由器主要工作在三层，它根据 IP 地址决定数据包的转发路径。

## 6.4 第 4 层：传输层

传输层负责端到端通信。

核心协议：

- TCP；
- UDP。

核心概念：

- 端口号；
- 可靠传输；
- 连接；
- 重传；
- 流量控制。

比如 TCP 的三次握手、四次挥手，就属于传输层相关内容。

## 6.5 第 5 层：会话层

会话层负责建立、管理和终止会话。

它关注的是通信双方之间的会话关系，比如：

- 会话建立；
- 会话保持；
- 会话恢复；
- 会话关闭。

在 TCP/IP 模型中，会话层的很多功能被合并到了应用层或其他协议实现中。

## 6.6 第 6 层：表示层

表示层负责数据的表示、编码、加密、压缩等。

它关注的是：

- 数据格式转换；
- 字符编码；
- 加密解密；
- 压缩解压；
- 序列化和反序列化。

例如：

- UTF-8 编码；
- JPEG、PNG 图片格式；
- TLS 加密；
- JSON、XML 数据表示。

在 TCP/IP 模型中，表示层也通常被合并到应用层中理解。

## 6.7 第 7 层：应用层

应用层直接服务于应用程序。

常见协议包括：

- HTTP；
- HTTPS；
- DNS；
- FTP；
- SMTP；
- SSH。

浏览器访问网站、客户端请求接口、邮件程序发送邮件，这些都属于应用层通信。

## 7. TCP/IP 模型和 OSI 模型的区别

TCP/IP 模型和 OSI 模型最大的区别是层数不同。

TCP/IP 模型通常使用四层或五层来描述，而 OSI 模型使用七层来描述。

可以这样对应：

| OSI 七层模型 | TCP/IP 模型 |
| ------------ | ----------- |
| 应用层       | 应用层      |
| 表示层       | 应用层      |
| 会话层       | 应用层      |
| 传输层       | 传输层      |
| 网络层       | 网络层      |
| 数据链路层   | 数据链路层  |
| 物理层       | 物理层      |

可以看到，OSI 模型中的会话层和表示层，在 TCP/IP 模型中通常被合并进应用层。

这也是为什么很多人说：

> TCP/IP 是实际使用的模型，OSI 是更适合学习和描述的模型。

## 8. 为什么 TCP/IP 赢了，但大家还在说 OSI？

从实际应用看，TCP/IP 模型是赢家。今天的互联网主要基于 TCP/IP 协议栈运行。

但是在网络工程师的日常表达中，OSI 模型仍然非常常见。

原因是 OSI 的层次划分更细，尤其适合描述问题和排查故障。

例如：

- 网线断了：Layer 1 问题；
- 交换机 MAC 表异常：Layer 2 问题；
- IP 配置错误：Layer 3 问题；
- TCP 端口不通：Layer 4 问题；
- HTTP 接口报错：Layer 7 问题。

这种说法非常简洁，也很容易定位问题范围。

所以即使 TCP/IP 是实际使用的模型，OSI 仍然是网络学习和故障排查中的重要语言。

## 9. 常见网络设备对应哪一层？

学习网络模型时，经常需要记住不同设备主要工作在哪一层。

| 设备                             | 主要工作层级            | 说明                           |
| -------------------------------- | ----------------------- | ------------------------------ |
| Hub 集线器                       | 第 1 层，物理层         | 只转发电信号，不理解 MAC 地址  |
| Repeater 中继器                  | 第 1 层，物理层         | 放大或再生信号                 |
| Switch 交换机                    | 第 2 层，数据链路层     | 根据 MAC 地址转发数据帧        |
| Bridge 网桥                      | 第 2 层，数据链路层     | 类似早期交换设备               |
| Router 路由器                    | 第 3 层，网络层         | 根据 IP 地址转发数据包         |
| Firewall 防火墙                  | 第 3、4、7 层都可能涉及 | 根据设备类型和功能不同而不同   |
| Wireless Access Point 无线接入点 | 第 1、2 层              | 既涉及无线信号，也涉及二层转发 |

需要注意的是，很多现代设备并不只工作在单一层。例如防火墙可能检查 IP、端口，也可能检查应用层内容；三层交换机既能做二层交换，也能做三层路由。

但在基础学习中，可以先记住它们“主要工作在哪一层”。

## 11. 用分层思维理解一次网络通信

假设你在浏览器中访问一个网站：

```text id="7rytp7"
https://example.com
```text

这个过程可以按分层模型理解。

在应用层，浏览器使用 HTTPS 协议请求网页。

在传输层，客户端和服务器之间建立 TCP 或 QUIC 连接，并使用端口号区分服务。

在网络层，数据包通过 IP 地址寻找目标服务器。

在数据链路层，本地网络中的交换机根据 MAC 地址转发数据帧。

在物理层，数据最终以电信号、光信号或无线信号的形式传输。

也就是说，一次简单的网页访问，背后其实经过了多层协议的协作。

分层模型的好处在于：每一层只需要做好自己的事情，不必关心所有细节。

应用层不需要关心电信号怎么传输，物理层也不需要关心 HTTP 请求的具体含义。各层通过标准接口协作，最终完成完整通信。

## 12. 为什么分层模型适合排查网络故障？

网络故障通常很复杂。如果没有分层思维，很容易不知道从哪里查起。

有了 OSI 或 TCP/IP 模型后，可以按层逐步排查。

例如网站打不开，可以这样分析：

第一步，看物理层：

```text id="oq7vx0"
网线插好了吗？
无线连接正常吗？
网卡亮灯吗？
```

第二步，看数据链路层：

```text id="cu2vbk"
能不能连上交换机？
MAC 地址学习正常吗？
VLAN 配置正确吗？
```text

第三步，看网络层：

```text id="preu8v"
IP 地址配置正确吗？
网关能 ping 通吗？
路由正常吗？
```

第四步，看传输层：

```text id="mchz5a"
目标端口通不通？
TCP 连接能不能建立？
防火墙是否拦截？
```text

第五步，看应用层：

```text id="q62pq5"
HTTP 服务是否正常？
DNS 是否解析正确？
应用程序是否报错？
```

这就是网络工程师经常说“从 Layer 1 查到 Layer 7”的原因。

## 13. 小测验：检查理解

## 13.1 哪个设备主要工作在 OSI 第二层？

答案是：交换机。

交换机主要根据 MAC 地址转发数据帧，因此它主要工作在数据链路层，也就是 OSI 第二层。

路由器主要工作在第三层，因为它根据 IP 地址转发数据包。

Hub 主要工作在第一层，因为它只转发电信号，不理解 MAC 地址。

## 13.2 哪些设备主要工作在物理层？

答案是：Hub 和 Repeater。

Hub 会把收到的电信号转发到其他端口。Repeater 会对信号进行再生或放大。它们都不理解 MAC 地址，也不理解 IP 地址，因此主要属于物理层设备。

## 14. 总结

网络模型的出现，是为了解决不同厂商、不同设备之间无法互相通信的问题。通过统一的分层标准，计算机网络才真正具备了开放性和互联能力。

TCP/IP 模型是今天互联网实际使用的协议模型，它定义了现代网络通信的基本方式。OSI 模型虽然没有成为互联网真正采用的主导实现模型，但它的七层结构非常适合学习、描述和排查网络问题。

简单总结：

- TCP/IP 是实际运行的互联网协议栈；
- OSI 是学习和排障时常用的理论模型；
- 物理层负责信号；
- 数据链路层负责 MAC 地址和局域网通信；
- 网络层负责 IP 地址和路由；
- 传输层负责 TCP、UDP 和端口；
- 应用层负责 HTTP、DNS、SMTP 等应用协议；
- OSI 中的会话层、表示层，在 TCP/IP 中通常被合并进应用层理解。

对于初学网络或准备 CCNA 的人来说，理解 TCP/IP 模型和 OSI 模型非常重要。它们不仅是考试知识点，更是后续学习交换、路由、TCP、UDP、DNS、HTTP、安全和故障排查的基础。
