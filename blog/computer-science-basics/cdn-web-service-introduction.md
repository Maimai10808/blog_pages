# 一文理解 CDN：为什么现代 Web 服务都离不开它？

## 1. CDN 是什么？

CDN，全称是 **Content Delivery Network，内容分发网络**。

它最早出现在 20 世纪 90 年代末，最初的主要目标是加速静态 HTML 内容的分发，让不同地区的用户都能更快地访问网页。随着 Web 应用的发展，CDN 的能力也在不断扩展。今天的 CDN 已经不只是“缓存静态文件”的工具，而是现代 HTTP 流量中非常重要的一层基础设施。

简单来说，CDN 的核心作用是：

> 把内容放到离用户更近的地方，让用户更快、更稳定、更安全地访问服务。

当用户访问一个网站时，如果所有请求都直接打到源站服务器，距离远的用户就可能面临较高延迟。比如服务器在美国，而用户在亚洲，那么请求需要跨越很长的网络路径，加载速度自然会受到影响。

CDN 的出现，就是为了缓解这个问题。

## 2. CDN 的核心思想：让内容离用户更近

CDN 会在全球各地部署大量服务器节点。这些节点通常被称为 **PoP**，也就是 **Point of Presence，接入点或节点机房**。

每个 PoP 中都会部署若干服务器，这些服务器通常被称为 **Edge Server，边缘服务器**。

当用户访问网站时，请求并不一定直接到达源站服务器，而是会先到达距离用户更近的边缘服务器。如果边缘服务器上已经缓存了用户需要的内容，就可以直接返回给用户。

这样做有几个明显好处：

- 用户访问速度更快；
- 源站服务器压力更小；
- 网络带宽消耗降低；
- 服务整体稳定性更强。

例如，一个用户访问网站中的一张图片。如果这张图片已经缓存在附近的 CDN 节点上，那么 CDN 可以直接把图片返回给用户，而不需要再回源站服务器获取。

这就是 CDN 最基础、也是最重要的价值。

## 3. CDN 如何把用户请求路由到最近节点？

CDN 的一个关键问题是：用户发起请求后，如何让请求到达“最近”或“最合适”的边缘节点？

常见的方式主要有两种：**DNS 路由** 和 **Anycast**。

## 3.1 DNS 路由

DNS 路由的思路是：不同的 CDN 节点拥有不同的 IP 地址。当用户查询某个域名时，DNS 系统会根据用户所在的位置，返回一个相对较近的 CDN 节点 IP。

例如：

- 中国用户访问时，DNS 返回亚洲节点；
- 欧洲用户访问时，DNS 返回欧洲节点；
- 北美用户访问时，DNS 返回北美节点。

这样，用户的请求就能被引导到距离自己较近的 PoP。

## 3.2 Anycast

Anycast 的方式更特殊。

在 Anycast 网络中，多个 CDN 节点可以共享同一个 IP 地址。当用户向这个 IP 发起请求时，网络会根据路由规则，把请求转发到距离用户最近或网络路径最优的节点。

简单理解：

> 多个地方都有同一个 IP，网络会自动帮用户找到最合适的那个节点。

Anycast 对大规模 CDN 非常重要，尤其在抗 DDoS 攻击方面也有很大优势。因为攻击流量可以被分散到全球多个节点，而不是集中打到一个机房。

## 4. 边缘服务器：带缓存的反向代理

CDN 的边缘服务器本质上可以看作一个带有巨大缓存能力的 **反向代理服务器**。

它站在用户和源站服务器之间，负责接收用户请求，并根据缓存情况决定如何处理。

一般有两种情况：

## 4.1 缓存命中

如果用户请求的资源已经存在于边缘服务器的缓存中，CDN 就可以直接返回资源。

这个过程非常快，因为请求不需要跨越很长的网络路径，也不需要源站服务器参与。

例如：

```text
用户请求图片
       ↓
CDN 边缘节点发现缓存中已有图片
       ↓
直接返回给用户
```text

这叫 **Cache Hit，缓存命中**。

## 4.2 缓存未命中

如果边缘服务器中没有这个资源，它就会向源站服务器请求一份资源，然后返回给用户，同时把这份资源缓存下来。

下次再有用户请求相同资源时，CDN 就可以直接从缓存中返回。

流程如下：

```text
用户请求资源
       ↓
CDN 缓存中没有
       ↓
CDN 回源站服务器获取资源
       ↓
返回给用户，并缓存到边缘节点
```

这叫 **Cache Miss，缓存未命中**。

通过这种方式，CDN 可以显著减少源站服务器的请求量和带宽压力。

## 5. CDN 不只是缓存静态文件

早期 CDN 主要用于缓存静态内容，例如：

- HTML；
- CSS；
- JavaScript；
- 图片；
- 字体文件；
- 视频文件。

但现代 CDN 的能力已经远不止这些。

很多 CDN 可以在边缘节点直接对内容进行优化处理。例如：

- 压缩 JavaScript 文件；
- 压缩 CSS 文件；
- 图片自动裁剪；
- 图片格式转换；
- 将 JPEG、PNG 转换为 WebP 或 AVIF；
- 根据设备类型返回不同尺寸的图片。

比如用户上传的是一张 PNG 图片，但浏览器支持 WebP 或 AVIF，CDN 可以在边缘节点自动转换格式，再把更小、更现代的图片格式返回给用户。

这可以减少传输体积，提高加载速度。

## 6. CDN 与 TLS：为什么动态内容也要走 CDN？

很多人以为 CDN 只适合静态资源，其实现在很多动态 HTTP 请求也会经过 CDN。

原因之一是：**TLS 连接可以在边缘节点终止**。

HTTPS 请求需要进行 TLS 握手。TLS 握手本身有网络往返成本，如果用户距离源站服务器很远，建立安全连接的延迟就会更明显。

当 TLS 在 CDN 边缘节点终止时，用户只需要和附近的边缘服务器建立加密连接，而不是直接和遥远的源站服务器完成 TLS 握手。

这样可以明显降低用户感知到的连接延迟。

也就是说，即使某些动态内容不能被缓存，让请求先经过 CDN 仍然可能带来性能收益。

## 7. CDN 的安全价值：抵御 DDoS 攻击

除了性能优化，现代 CDN 还有一个非常重要的作用：安全防护。

其中最典型的就是 **DDoS 防护**。

DDoS 攻击的基本思路是：攻击者利用大量机器向目标服务器发送海量请求或流量，让服务器无法正常处理真实用户请求，最终导致服务不可用。

如果网站没有 CDN，攻击流量可能直接打到源站服务器，源站很容易被压垮。

但如果网站接入 CDN，攻击流量会先到达 CDN 的边缘网络。大型 CDN 通常拥有巨大的全球带宽和节点容量，可以吸收、过滤和分散攻击流量。

尤其是基于 Anycast 的 CDN 网络，可以把攻击流量分散到全球多个 PoP 中，而不是集中到单个源站。

这使得 CDN 成为现代 Web 安全架构中非常重要的一环。

## 8. CDN 的可用性价值：提高服务稳定性

CDN 还能提升系统可用性。

因为 CDN 本身是高度分布式的，它在全球多个地区都有节点。当某个节点出现故障时，请求可以被调度到其他可用节点。

同时，静态资源如果已经缓存在多个 CDN 节点中，即使源站短时间不可用，CDN 仍然可能继续向用户提供已缓存的内容。

这对大型网站、新闻平台、电商平台、视频平台等服务非常重要。

CDN 提升可用性的方式包括：

- 多节点分布；
- 缓存内容副本；
- 自动故障切换；
- 降低源站压力；
- 缓解突发流量冲击。

例如在大促、热点新闻、直播活动等高流量场景中，如果所有用户请求都直接打到源站，系统很容易出现瓶颈。CDN 可以在边缘层分担大量流量，让源站保持稳定。

## 9. CDN 对源站有什么帮助？

接入 CDN 后，源站服务器不再需要处理所有用户请求。

CDN 可以帮源站承担大量工作：

- 缓存静态资源；
- 减少重复请求；
- 降低带宽消耗；
- 处理 TLS 握手；
- 抵御恶意流量；
- 优化图片和脚本；
- 提供更高的全球访问速度。

这意味着源站可以把更多资源用于处理真正需要动态计算的业务逻辑，例如：

- 用户登录；
- 下单支付；
- 数据查询；
- 个性化推荐；
- 后台管理；
- API 业务处理。

CDN 相当于站在系统最外层的一道“性能与安全屏障”。

## 10. 哪些内容适合使用 CDN？

最适合 CDN 的内容通常是访问频繁、变化不频繁、可以被缓存的资源。

例如：

- 网站 Logo；
- 商品图片；
- 用户头像；
- CSS 文件；
- JavaScript 文件；
- 字体文件；
- 视频文件；
- 下载文件；
- 静态 HTML 页面。

但现代 CDN 也可以用于动态请求，只是动态请求通常不能简单缓存。即便如此，动态请求经过 CDN 仍然可以获得 TLS 终止、网络加速、安全防护、流量清洗等收益。

所以现在更合理的理解是：

> 只要你在对外提供 HTTP 服务，就应该考虑使用 CDN。

## 11. CDN 的工作流程总结

一个典型的 CDN 请求流程如下：

```text
用户访问网站
       ↓
DNS 或 Anycast 将请求路由到附近 CDN 节点
       ↓
边缘服务器检查缓存
       ↓
如果缓存命中，直接返回资源
       ↓
如果缓存未命中，回源站获取资源
       ↓
CDN 返回资源给用户，并缓存副本
```

这个过程看起来简单，但背后涉及全球网络调度、缓存策略、协议优化、安全防护和高可用架构。

CDN 之所以重要，是因为它解决的不只是“快一点”的问题，而是同时解决性能、安全、成本和可用性问题。

## 12. 总结

CDN，即内容分发网络，是现代 Web 架构中非常重要的一层基础设施。

它通过在全球各地部署 PoP 和边缘服务器，把内容放到离用户更近的地方，从而提升访问速度。边缘服务器作为反向代理，可以缓存静态资源，减少源站压力，并降低带宽消耗。

现代 CDN 还具备更多能力，例如图片格式转换、资源压缩、TLS 终止、DDoS 防护和故障容错。即使是不能缓存的动态 HTTP 请求，也可以通过 CDN 获得网络加速和安全防护收益。

如果说 HTTP 是 Web 通信的基础协议，那么 CDN 就是让 HTTP 服务在全球范围内更快、更稳、更安全的重要基础设施。

对于开发者来说，只要你的服务需要对外提供 HTTP 流量，CDN 都应该成为系统设计中优先考虑的一部分。
