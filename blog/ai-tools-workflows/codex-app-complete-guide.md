## 一、安装前准备：Git、Node.js 和 VS Code

在安装和使用 Codex App 之前，建议先准备好三个基础工具：

Git
Node.js
VS Code

Git 用来进行代码版本管理，Node.js 用来运行前端项目，VS Code 用来查看和编辑代码。

如果你之前没有配置过开发环境，可以先把这三个工具安装好。完成这些准备以后，再进入 Codex 官网下载安装包。

Codex 支持 Windows 和 Mac 两大操作系统。官网会根据你的系统自动提供对应安装包。

Windows 和 Mac 版本的核心功能基本一致。唯一需要注意的是，Computer Use，也就是自动操作电脑的能力，目前主要在 Mac 上使用。后面讲到这部分时，可以切换到 Mac 电脑进行演示。

安装过程比较简单，一路点击下一步即可。

安装完成后，启动 Codex App，选择 ChatGPT 账户登录。现在 ChatGPT 免费账户也可以使用 Codex，不过额度相对较低。

第一次进入软件时，Codex 会让你选择希望它处理什么类型的工作。它会根据你的选择预装一些内置插件和 Skills。进入软件以后，也可以在设置里继续安装或修改这些插件。

接着需要选择主要使用场景，是编程，还是日常工作。这个选项后续也可以在设置里修改。

最后点击“设置沙盒”按钮，完成沙盒初始化。关于沙盒的作用，后面会详细讲。

## 二、三栏布局：任务列表、对话窗口和多功能区域

Codex App 是非常经典的三栏布局。

左侧是任务列表。
中间是对话窗口。
右侧是多功能区域。

左侧任务列表用来管理项目、对话和任务状态。
中间对话窗口是我们和 AI 交流的地方。
右侧多功能区域可以用来查看文件、预览网页、查看浏览器、操作终端等。

我们可以先创建两个项目文件夹，来理解 Codex 的基础工作方式。

比如在桌面新建两个文件夹，分别作为两个项目。然后回到 Codex，点击进入项目工作，选择使用现有文件夹，先选择第一个文件夹。

在第一个项目里，可以输入需求：

```text
做一个 HTML 单页面的宠物洗护店网页。
```

这时左侧边栏会增加一个项目，项目名称就是文件夹名称，里面会展示正在运行的任务。

接着点击左上角的新对话按钮，Windows 快捷键是 Ctrl + N，Mac 快捷键是 Command + N。开启新对话时，可以选择它属于哪个项目。

比如选择添加新项目，把第二个文件夹也添加进来，然后输入需求：

```text
用 React 框架做一个网页版待办事项提醒工具。
```

这样 Codex 就可以同时处理多个项目。

在两个项目并行工作的同时，还可以继续开启更多对话。比如把鼠标移动到第二个项目上，点击项目旁边的小按钮，在项目里开启新的对话，然后询问：

```text
React 框架是什么？
```

这时就可以看到，Codex 同时开启了多个任务，并且这些任务分别属于不同项目。

正在执行的任务上会有一个转圈的小图标，表示 AI 正在工作。等待一段时间后，任务状态会发生变化。

绿色标签表示等待批准。
蓝色小点表示任务已经完成。
转圈图标表示任务还在执行中。

如果任务显示等待批准，通常说明 Codex 需要联网下载依赖、访问外部资源，或者执行某些需要用户确认的操作。确认批准后，任务会继续执行。

Codex 的任务列表非常简洁，也非常适合观察多个任务的执行状态。它可以同时开启多个工作任务，并且能在多个任务之间快速切换。

## 三、左侧任务列表：搜索、重命名和归档

左侧边栏最上方的新对话按钮，可以用来开启新的对话。

新对话可以选择某个项目，也可以不选择任何项目。不属于任何项目的对话，会被收录到左侧任务列表最下面的“对话”区域里，更像普通聊天。

左侧边栏还有搜索按钮，Windows 快捷键是 Ctrl + G，Mac 快捷键是 Command + G。

这个功能可以搜索近期对话历史。不过目前它主要搜索对话标题，不能搜索对话里的完整内容。

每个对话标题通常是 AI 根据对话内容自动摘要生成的。我们也可以选择某个对话，双击后手动重命名。

如果不再需要某个对话，可以点击归档按钮。归档后，对话会从左侧边栏消失。

但归档不是彻底删除。进入设置里的“归档对话”，仍然可以找到已经归档的对话，并且可以取消归档，把它恢复回来。

左侧还有插件和自动化按钮，这两个后面再展开讲。

## 四、沙箱与权限控制：Codex App 的安全地基

Codex App 的权限控制是围绕沙箱展开的。

这一点和 Cloud Code 有本质区别。Cloud Code 的沙箱更像是一层可以额外开启的保护，而 Codex App 的沙箱是整个权限系统运行的基础。

Codex 会把当前项目文件夹作为一个沙箱来管理。

在默认权限下，Codex 可以读取和修改沙箱内的所有文件。也就是说，在项目文件夹内部，它可以直接修改文件，不会每改一个文件都来问你一次。

我认为这点非常符合正常使用习惯。否则每次修改都要逐个批准，效率会非常低。

当然，如果你希望更严格，也可以在设置里调整为逐个文件修改都需要审批。

Codex 沙箱有两个默认限制：

第一，Codex 不能修改沙箱外的文件。
第二，Codex 默认禁止联网。

这两个限制不是靠模型自觉遵守，而是使用操作系统底层机制实现的。不同操作系统的实现机制不同，比如 macOS 使用的是系统内置的 sandbox 机制。

这个沙箱机制其实就是最近很火的 harness engineering，也就是“驯服工程”的典型实现。

AI 就像一匹能力很强的马，而沙箱、权限和审批机制，就是套在它身上的马具。它们并不是削弱 AI 的能力，而是把 AI 的能力限制在一个可控范围内。

如果 Codex 需要修改沙箱外文件，或者需要联网，就会向用户申请权限。这个操作叫 escalate，也就是提权。

默认情况下，提权操作需要人工审核同意。

Codex 还提供了第二个档位，也就是自动审查。开启自动审查后，Codex 会调用一个小模型，对提权操作进行安全性审查。如果是低风险操作，就会自动放行；如果是高风险操作，才会触发人工审查。

这是我最推荐的模式。

自动审查可以让大部分低风险操作不需要人工批准，在保证较高安全性的同时，显著提高使用便利度。

第三个档位是完全访问权限。开启以后，Codex 会无视沙箱限制，可以在电脑上执行几乎所有操作。开启时，软件会出现非常醒目的风险提示。

这个模式一定要谨慎使用。

## 五、上下文、模型和额度管理

在权限控制右侧，有一个圆圈，展示当前上下文使用情况。

这里的中文翻译可能不太准确，更准确的理解应该是“上下文使用量信息”。它显示的是当前对话里的历史内容占用了多少模型上下文空间。

当上下文超过限制时，Codex 会自动压缩历史对话，从而释放更多上下文空间。

我们也可以输入斜杠，选择“压缩”选项，手动触发一次上下文压缩。

压缩完成后，Codex 会把之前对话中不重要的内容排除掉。这可以提高 AI 的专注度，也能降低 token 消耗。

不过在 AI Agent 使用经验里，有一个常见原则：

清空通常好于压缩。

因为过多历史上下文会干扰 AI 的注意力。一个任务执行完以后，最好开启一个新的对话，让上下文重新变干净。这样 AI 更容易把注意力集中在新任务上。

上下文窗口右侧是模型选择。

可以根据任务复杂程度选择模型和思考强度。一般情况下，选择最新模型即可，比如 ChatGPT 5.5。

下面还有速度选项，可以选择标准或快速。快速模式下，AI 推理速度会提升，但会消耗更多套餐用量。如果任务很急，同时套餐余量还比较充足，可以开启快速模式。

套餐余量可以在左下角设置里查看。

这里通常有两个限额：五小时限额和周限额。任意一个达到上限后，Codex 都不能继续使用。两个限额都有对应重置时间，时间到了以后额度会恢复。

右侧还有语音输入功能，可以把和 AI 的交互从打字变成说话。对于描述复杂需求来说，语音输入非常适合。

## 六、AI 生图、Steer 和运行中纠偏

Codex 内置了 AI 画图能力，而且可以调用很强的图像生成模型。

比如让它生成宠物洗护店网页时，它可能会自动为网页配一些图片。但这些图片有时可能来自网络免费素材，和具体场景不完全匹配。

比如网页里的店内环境图，如果展示的只是宠物图片，而不是宠物洗护店真实空间，就不够合适。门店地图如果画得太粗糙，也需要调整。

这时可以新开一个对话，让 Codex 调用 AI 绘图能力：

```text
调用 AI 绘图功能，绘制三个店内环境轮播图。三张图分别展示店内不同区域，并保持店内装修风格一致。
```

Codex 可以生成三张风格一致的店内环境图，并替换到网页里。

如果还要修改门店地图，可以给它提供地址和截图：

```text
我们的店在陕西北路 1620 号，就是地图上标记的这个点。请按我发给你的位置，用可爱清新的宠物风格地图，把我们的店标记上，并修改网页里的门店位置信息。
```

可以直接把地图截图复制粘贴进对话窗口。

如果在执行过程中发现 Codex 理解错了，比如它没有调用 AI 生图，而是用 SVG 生成了一张效果很差的地图，就可以使用 Steer 功能进行纠偏。

Steer 可以理解为“打方向盘”。当 AI 正在执行任务时，如果方向不对，就不要让它继续跑。此时可以中途接管方向，人工引导它修正。

比如发送：

```text
你这图不行，应该调用 AI 绘图能力重新生成。
```

默认情况下，这条新指令会进入队列，等上一轮执行完再处理。但我们可以点击“引导”按钮，或者使用快捷键 Ctrl + Enter，把这条指令插入当前任务中。

这样 Codex 就会在运行中途修正方向。

在设置里还有一个“跟进行为”，可以设置执行过程中输入的新指令是排队，还是直接进入引导。一般建议保持默认排队，只有需要干预时再手动点击引导。

## 七、Plan 模式：复杂任务先对齐计划

在对话窗口的加号里，可以添加照片、文件，也可以调用插件和计划模式。

对于复杂任务，建议先开启 Plan 模式。

开启 Plan 模式后，Codex 不会立即开始修改文件，而是先输出一份工作计划，并向用户确认。确认以后才开始执行。

比如我们可以输入：

```text
把这个项目改造成 Next.js 框架。
```

在 Plan 模式下，Codex 会倾向于用问题卡片和用户沟通，例如：

希望使用哪种项目形态？
是否使用 App Router？
是否使用 TypeScript？
样式迁移怎么处理？
迁移完成后是否启动本地服务器验证？

用户逐步选择后，Codex 会生成一份完整计划。确认计划没有问题后，点击“实施此计划”，它才会开始编写代码。

代码写完以后，Codex 可以启动内置浏览器进行自动化测试。右侧多功能区域会自动打开浏览器，展示项目运行效果。

如果页面里有不满意的地方，可以点击批注按钮，选中某个元素，直接添加评论，让 AI 修改。

比如看到星星图标是空心的，可以批注：

```text
为什么这个星星是空心的？
```

发送后，Codex 会根据批注修改代码。刷新页面后，就能看到修改效果。

通过 Plan 模式配合内置浏览器，可以非常稳地完成复杂项目迁移和页面修改。

## 八、Codex 不是 IDE，但可以联动 VS Code

Codex App 并不是传统 IDE，它不提供完整代码编辑能力。

右上角可以切换文件树，虽然可以查看代码，也可以点击某一行写批注，但不能像 VS Code 那样直接编辑代码。

所以如果要进行更细致的代码管理，还是需要借助第三方 IDE。

在使用 VS Code 前，最好先把项目初始化成 Git 工程。可以新开一个对话，让 Codex 执行：

```text
把项目初始化成一个 Git 工程，注意排除掉不需要提交的文件。
```

Codex 会先创建 `.gitignore` 文件，把不需要提交的内容排除出去，然后初始化 Git 仓库。

项目初始化成 Git 仓库以后，右上角会出现更多按钮，其中就有 VS Code 按钮。点击后，可以直接用 VS Code 打开项目。

下拉列表里还可以选择其他 IDE。如果电脑上安装过对应 IDE，就可以关联出来。

也可以在设置中选择默认打开的 IDE。

## 九、使用 Git 和 GitHub 管理代码

Codex 可以通过对话完成很多 Git 和 GitHub 操作。

比如让它把代码推送到 GitHub。

不过第一次推送前，需要先在 GitHub 上创建一个仓库。创建仓库后，把仓库地址复制给 Codex，它就可以帮你完成远程仓库绑定和代码推送。

这属于基础 Git 操作，这里不展开讲。

这里重点讲两个进阶技巧：

第一，使用 Git 对开发过程进行回滚。
第二，使用 Git Worktree 并行开发。

## 十、用 Fork 对话分叉 + Git 回滚，撤销不满意的改动

假设你让 Codex 添加了一个“期望到店时间”字段，并且效果不错。完成后可以点击提交，把本次代码修改保存成 Git commit。

接着你又让它把“期望到店时间”移动到联系人上方，但发现页面更难看了。这时想要回退到之前状态，最好同时回滚代码和对话历史。

第一步，回滚对话。

找到上一次对话结束的位置，点击分叉按钮，选择派生到本地。Codex 会在你点击的位置复制出一份新对话，新对话会剔除掉后面不想保留的部分。

不过分叉只能回退对话历史，不能同步回退代码。

第二步，回滚代码。

在 VS Code 的 Source Control 里找到想回退到的那次 Git 提交，右键复制 commit hash。

然后回到 Codex，告诉它：

```text
把代码回退到这个提交状态：<commit hash>
```

执行完成后，代码也会恢复到对应状态。

这样就可以通过 Codex 的对话分叉功能，加上 Git 操作，把一次不需要的改动从对话层面和代码层面都回滚掉。

## 十一、Git Worktree：并行开发多个任务

Git Worktree 听起来复杂，其实本质很简单。

它就是用 Git 创建一个新的分支，然后把这个新分支的代码完整复制到一个新的文件夹里。这个新文件夹就是一个 worktree。

主文件夹和分支文件夹可以并行工作。你可以在不同文件夹里各自修改代码，互不干扰。

比如在宠物洗护项目里，可以右键创建永久工作树：

第一个 worktree 专门优化客户评价部分，命名为 customer-rating。
第二个 worktree 专门优化门店信息和地图部分，命名为 store-info。

这样 Codex 会把项目复制到两个不同文件夹中，每个文件夹对应一个分支。

然后可以分别在两个分支上开对话：

```text
优化客户评价部分，多写几个评价，做一个动画轮播效果。
```

另一个分支输入：

```text
优化门店信息部分，让门店信息和地图上下排列，不要左右排列，把地图展示全。
```

因为它们位于不同文件夹，所以两个任务可以并行开发，不会互相影响。

等两个分支都开发完以后，可以分别输入：

```text
合并回主干。
```

Codex 会把 worktree 的改动合并回主项目。

合并完成后，主干项目同时拥有两个分支的修改。临时分支使用完毕后，可以右键移除。

这种方式非常适合多个功能并行开发，也适合让 AI 同时尝试不同方案。

## 十二、Codex 云端运行环境

Codex 的任务不仅可以在本地运行，也可以在云端运行。

比如修改代码、处理文件、执行一些不依赖本机环境的任务，都可以让云端环境完成。

使用云端环境的前提是，项目代码需要同步到 GitHub。

先点击右上角推送按钮，确保本地代码和 GitHub 远端代码一致。然后在运行模式里选择关联 Codex Web，把这个项目初始化成网页版也能使用的项目。

点击前往 Cloud，选择对应代码仓库，然后输入任务需求。

比如：

```text
把首页的期望到店日期设置成明天早晨 09:30。
```

Codex 会在云端初始化运行环境，把 GitHub 代码下载进去，然后分析项目并完成修改。

完成后，可以点击创建 Pull Request，再到 GitHub 页面查看 PR。确认没问题后，点击 Merge，把代码合并进主干分支。

回到本地项目后，在 VS Code 里点击 Sync Changes，把 GitHub 上的最新代码同步到本地。

这样就完成了从云端修改、GitHub 审核合并、本地同步的完整流程。

Codex 网页版也可以用手机打开。它很适合出门在外时使用。没有电脑时，也可以让 Codex 在云端完成代码修改，我们只需要用手机进行审批。

## 十三、项目记忆系统：AGENTS.md

每次开启新对话，都是一个全新的上下文。AI 不记得之前聊过什么，也不知道项目背景。

如果项目变复杂，每次都重新解释项目背景，或者让 AI 自己读代码摸索，会非常低效。

解决这个问题的常见方式，是在项目根目录创建一个 `AGENTS.md` 文件。

这个文件在 Claude Code、OpenCode 等其他 AI Agent 工具里也比较通用。它可以理解为 AI 每次对话时必读的项目指南。

有了这个文件后，后续和 Codex 的对话都会带上它的内容作为上下文。

比如可以在 `AGENTS.md` 里写：

```markdown
我叫技术爬爬虾，擅长 Python 和 Java，对 CSS 一窍不通。遇到网页样式问题时，需要用大白话给我解释。
```

然后新开一个对话问 Codex：

```text
我叫什么，擅长什么技术？
```

它就可以自动读取 `AGENTS.md`，并把其中内容带入对话。

如果自己写 `AGENTS.md` 觉得麻烦，也可以让 Codex 生成：

```text
请通读当前文件夹，把你学到的关于项目的知识保存到 AGENTS.md 文件里。
```

Codex 会把项目的重要信息写入这个文件。后续新开对话时，它就能更快理解项目。

对于复杂项目来说，`AGENTS.md` 基本是必写文件。

## 十四、全局 AGENTS.md 与安全提示词

项目根目录里的 `AGENTS.md` 只对当前项目生效。

Codex 还提供了全局 `AGENTS.md`，可以对这台电脑上的所有项目生效。

进入 Codex 左下角设置，在个性化里的自定义指令中编辑，它对应的就是全局 `AGENTS.md`。

比如可以添加一条安全规则：

```text
禁止使用脚本批量删除文件或目录。只能使用 remove item 一个一个文件进行删除。如果必须批量删除文件，应该停止操作，让用户手动处理。
```

保存后，这条规则会对所有项目生效。

对应文件通常位于用户目录下的 `.codex/AGENTS.md`。

Codex 也有一个实验性的记忆功能，可以从聊天里生成新记忆，并带入新聊天。不过它目前还是实验功能，这里不展开介绍。

## 十五、插件：让 Codex 接入外部服务

在 Codex 左侧边栏点击插件，可以进入官方插件市场。

这里有两类能力：插件和技能。

插件一般是第三方服务为 Codex 编写的软件包。第三方服务可以把自己的能力通过插件注入 Codex。

比如可以安装 GitHub 插件和 Gmail 插件。

安装 Gmail 插件时，浏览器会弹出 Google 登录窗口。登录授权后，显示 Gmail 已连接，就说明配置成功。

之后可以在对话里通过斜杠调用插件。

比如先调用 GitHub 插件：

```text
你看一下我 star 数量前十的开源项目，还有大概数据。
```

再调用 Gmail 插件：

```text
用我的账户发邮件给我自己，做一个摘要。
```

Codex 可以先读取 GitHub 上 star 数量前十的项目，再通过 Gmail 给自己发送摘要邮件。

如果希望每周都运行一次，还可以直接说：

```text
很好，你把上述工作做成一个自动化，然后每周五下午四点都发邮件给我。
```

Codex 会创建自动化任务。之后可以在左侧自动化区域查看，也可以编辑执行时间、模型和任务内容。

自动化任务还可以立即运行测试。

Codex 有一个很好的细节：如果它在自动化执行中积累了经验，会写入一个 `memory.md` 文件，用来帮助下一次自动化更稳定地执行。

## 十六、Automation：定时任务的玩法

自动化功能配合浏览器自动化和 Computer Use，会有更多玩法。

比如可以让它每天定时：

打开某个网站签到。
汇总当天 Teams 聊天记录。
生成工作日报。
检查 GitHub 看板进度。
调研某个平台的热门话题。
给老板或团队发送总结。

在创建自动化时，可以选择运行位置、项目、执行时间和模型。

简单任务可以选择迷你模型，复杂任务则建议选择更强的模型。

## 十七、Skills：给 AI Agent 的专业技能包

Skills 可以理解为给 AI Agent 的专业技能包，或者带目录结构的说明书。

我们可以把工作流、专业能力、操作规范封装成一个个 Skill，让 AI 在执行特定任务时更稳定、更高效，输出也更可靠。

在 Codex 里，安装 Skills 大致有三种方式：

官方 Skills
第三方 Skills
自己编写 Skills

## 十八、官方 Skills：以 Remotion 为例

Codex 插件和技能市场里可以找到官方技能。

比如 Remotion 是一个用编程方式创建动画视频的工具。安装后，可以创建一个 Remotion 项目文件夹，然后在 Codex 中添加新项目。

通过斜杠调用 Remotion Skill，输入：

```text
帮我生成一个 3D 圆锥摆的视频动画，需要有受力分析，角速度随时间缓慢增大。
```

Codex 会调用 Remotion 技能，学习如何使用 Remotion 创建视频，最后生成完整视频，并打开一个网页版剪辑工具。

这样就可以通过官方 Skill 生成动画视频。

## 十九、第三方 Skills：以网页版 PPT 为例

第三方 Skills 可以从 GitHub 下载。

比如有些作者开发了电子杂志风格的网页版 PPT Skill，可以生成适合线下分享、行业演讲、个人风格演讲的网页 PPT。

安装方式一般是：

下载 Skill 压缩包。
在项目文件夹里创建 `.codex/skills` 目录。
把下载的 Skill 放进去。
回到 Codex 添加这个项目。
通过斜杠调用对应 Skill。

比如输入：

```text
根据以下材料生成 PPT。
```

然后把文案粘贴进去，Codex 就会根据 Skill 的规范生成一套网页版 PPT。

效果通常会比较完整，既能提炼重点，也能加上动效，适合直接用于演示或录制视频。

## 二十、自制 Skills：把视频和字幕转成图文教程

除了使用官方和第三方 Skills，也可以自己创建 Skill。

比如作为视频博主，经常有一个需求：把视频转换成图文笔记，发布到各个平台。

这类重复工作就适合封装成 Skill。

可以新建一个项目文件夹，把视频和字幕文件放进去。然后在 Codex 中调用内置的 Skill Creator。

输入需求时，可以写清楚完整工作流：

```text
创建一个 Skill。当我提供视频和字幕文件时，第一步读取字幕文件，转换成 Markdown 笔记。要求自动添加标点、划分段落。

如果某一句涉及代码讲解、UI 交互，或者能借助视觉材料理解内容，就在这句末尾添加一个截图标记。

第一步做完后，第二步调用 ffmpeg，在每个截图提示位置进行截图，然后用本地图片替换掉 Markdown 里的截图占位符。
```

Codex 会用 Skill Creator 把这个流程固化成可复用的 Skill。

生成后，通常会交付一个 `SKILL.md` 文件，以及相关脚本，比如用于批量截图和替换图片的 Python 脚本。

之后只要新开对话，调用这个自制 Skill，再告诉它：

```text
我准备了字幕和视频，帮我转换。
```

它就会读取字幕和视频，根据 Skill 的流程生成 Markdown 图文教程。

这种方式非常适合把重复工作流程沉淀下来。

## 二十一、MCP：给 Codex 接入标准化工具箱

MCP 全称是 Model Context Protocol，也就是模型上下文协议。

简单来说，MCP 是大模型的标准化工具箱。大模型可以通过这些工具与外部系统互动，获取信息，并完成具体任务。

在 Codex 里，MCP 的入口比较深。可以进入左下角设置，找到 MCP 服务器，然后添加服务器。

比如要给宠物洗护项目增加数据库，可以使用 Supabase MCP。

Supabase 是一个开源免费的 Postgres 云端数据库服务。

基本流程是：

在 Supabase 创建新项目。
点击 Connect。
找到 MCP 客户端。
选择 Codex。
复制它提供的 URL。
回到 Codex 添加 MCP 服务器。
选择流式 HTTP 传输方式。
填写 URL，并命名为 Supabase MCP。

保存后，还需要在终端执行登录命令：

```bash
codex mcp login supabase
```

浏览器会自动打开授权窗口，点击授权后，Supabase MCP 就配置完成了。

授权完成后，最好重启一次 Codex。

然后可以输入：

```text
使用 Supabase MCP 创建一个预约业务表。我的需求是把用户的表单存入预约业务表里面，数据库写入操作应该从后端用 service role 的形式写入。
```

Codex 会调用 Supabase MCP 创建预约表，并在项目后端加入新的端点，用 Postgres 连接池写入数据。

接着需要在 `.env.local` 里填入 Supabase 的连接地址。填好后，让 Codex 重启项目。

然后在浏览器里填写表单并提交，就可以在 Supabase 的 Table 页面看到预约数据。

这样就通过 MCP 给前端项目接入了后端数据库能力。

## 二十二、Netlify：把项目部署到公网

Codex 也可以通过插件把项目部署到 Netlify。

Netlify 是一个可以免费部署静态网页、Node.js 项目和 Next.js 项目的平台。

在插件市场里安装 Netlify 插件后，用 GitHub 登录授权。

然后可以让 Codex 执行：

```text
帮我把这个项目部署到 Netlify 上面。
```

Codex 会识别项目框架，比如 Next.js，然后把项目部署到 Netlify，并返回一个公网可访问的域名。

打开这个域名，就能看到部署完成的网站。

Netlify 的一个好处是，生成的网站域名在国内通常也能比较方便地直连访问。

## 二十三、Computer Use：让 Codex 自动操作电脑

最后是 Computer Use，也就是电脑自动化。

这个功能目前主要在 Mac 上使用。

安装 Computer Use 插件后，新开一个对话，调用 Computer Use，然后输入：

```text
你打开聊天软件，找到老板，发送“你好”。
```

Codex 会自动操作电脑，打开聊天软件，找到对应联系人，并在发送前询问你是否确认。确认后，消息就会发出。

再复杂一点的场景，比如给 Codex 一个 GitHub 上的项目进度看板，让它打开看板，汇总团队所有工单进度，然后生成英文简报发送给老板。

执行过程中，Codex 会申请授权调用 Chrome 浏览器。确认后，它会打开浏览器，查看看板内容，分析工单进展，然后生成总结。

Computer Use 的体验比较特别，因为它使用虚拟鼠标在后台运行，不会完全占用当前窗口。

完成后，它会再次询问你是否确认发送。确认后，消息才会发出。

这类流程还可以进一步做成自动化：

```text
很好，你把以上流程做成一个自动化，然后每天下午 5 点下班的时候都发一个简报给老板。
```

Codex 会把这个流程编排成定时任务。之后可以在左侧自动化区域找到这个任务。任务内容就是每天 5 点打开 GitHub 看板，总结项目进展，然后通过聊天软件发送给老板。

如果想长期运行这种自动化任务，最好在设置里打开“运行时防止系统休眠”的开关。

这个开关主要是 Mac 上需要处理，Windows 通常不需要单独设置。

## 二十四、最后总结

Codex App 已经不是一个简单的聊天工具，也不是一个普通代码助手。

它更像是一个集成了项目管理、文件操作、代码生成、浏览器预览、AI 生图、Git、GitHub、云端运行、插件、Skills、MCP 和电脑自动化的 AI 工作台。

它的核心能力可以概括为几句话：

用项目文件夹作为工作空间。
用沙箱和权限控制保证安全。
用任务列表管理多任务并行。
用 Plan 模式降低复杂任务跑偏的概率。
用 Steer 在执行过程中及时纠偏。
用 Git 和 Worktree 管理代码改动与并行开发。
用 AGENTS.md 给项目增加长期记忆。
用插件、Skills 和 MCP 扩展外部能力。
用 Automation 和 Computer Use 执行长期自动化任务。

对于开发者来说，它可以完成从写代码、改页面、测试、部署到 GitHub 协作的完整流程。

对于非开发者来说，它也可以用来写文档、做 PPT、处理数据、生成图文教程、整理日报、自动发送消息。

真正把 Codex App 用顺手以后，它不只是一个 AI 对话框，而更像是一个可以长期协作的智能工作助手。
