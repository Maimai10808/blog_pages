# 写给 Web3 从业者的期货入门：从合约规格、保证金到永续合约

很多 Web3 开发者第一次接触交易系统时，往往是从现货、永续合约、期权、杠杆、保证金这些词开始的。

如果只是写页面，可能一开始会觉得它们只是不同的按钮和字段：

```text
现货买入
现货卖出
开多
开空
杠杆
保证金
强平价
资金费率
计划委托
止盈止损
```

但如果你想真正理解交易系统，就不能只停留在“接口怎么调、组件怎么写”。你需要知道这些字段背后的金融含义。

期货就是一个非常好的入口。

因为加密货币里的永续合约，本质上也是从期货这类衍生品发展出来的。理解了传统期货，再看 Web3 里的永续合约、链上衍生品、保证金交易、清算机制和预言机价格，就会清楚很多。

这篇文章不是写给专业交易员的，而是写给 Web3 从业者、前端工程师、产品经理和交易系统开发者的期货入门。

---

## 一、期货到底是什么？

期货 Futures，可以理解为：

> 交易双方约定在未来某个时间，以约定规则买卖某个标的资产的标准化合约。

这里有几个关键词：

```text
未来
标的资产
合约
标准化
交易所
保证金
结算
```

举个简单例子。

假设现在 BTC 是 60,000 USDT。
你和别人约定：一个月后按照某个合约规则交易 BTC。

你买入这个期货合约，不一定是为了真的拿到 BTC；你可能只是想通过 BTC 价格上涨赚钱。
你卖出这个期货合约，也不一定是你真的有 BTC 要卖；你可能是在表达对 BTC 价格下跌的判断，或者是在对冲现货风险。

所以期货不是简单的“买币”或“卖币”，而是交易一个围绕标的资产价格变化设计出来的合约。

从 Web3 角度理解：

```text
现货交易：我真的买到了 BTC 或 ETH
期货交易：我交易的是 BTC 或 ETH 的未来价格风险
永续合约：没有到期日的期货式合约
期权交易：我买的是未来买入或卖出的权利
```

期货的核心不是“资产本身”，而是“价格风险”。

---

## 二、为什么会有期货？

期货最早不是为了让大家高杠杆投机，而是为了解决现实世界里的价格风险。

比如一个农民种小麦。
他担心几个月后小麦价格下跌，于是提前通过期货锁定未来卖出价格。

再比如一个食品加工企业。
它担心未来小麦价格上涨，于是提前通过期货锁定未来买入成本。

这就是期货最重要的功能之一：**套期保值 Hedging**。

当然，市场里也有另一类参与者：投机者 Speculator。

投机者不一定真的需要小麦、石油、黄金或 BTC。他们参与期货市场，是为了根据价格涨跌获取收益。

所以期货市场里大概有两类人：

```text
套保者：用期货降低现实业务里的价格风险
投机者：主动承担价格风险，希望从波动中获利
```

放到 Web3 里也一样。

一个矿工、做市商、协议金库或持有大量 ETH 的机构，可能用衍生品对冲风险。
一个普通交易者可能用永续合约开多或开空，希望赚价格波动的钱。

## 三、期货和现货有什么区别？

这是最基础，也最容易混淆的地方。

### 现货

现货交易的是资产本身。

比如你买 ETH/USDT：

```text
你付出 USDT
你得到 ETH
```

你的账户里真的多了 ETH。

### 期货

期货交易的是标准化合约。

你买入 BTC 期货，不代表你立刻拿到 BTC。
你是在建立一个和 BTC 未来价格相关的头寸。

可以这样理解：

```text
现货：买卖资产
期货：买卖价格风险
```

在前端页面里，现货和期货的差异会直接体现在字段上。

现货页面通常关注：

```text
买入价格
卖出价格
买入数量
卖出数量
可用余额
当前委托
历史委托
```

期货或永续合约页面还要关注：

```text
开多
开空
杠杆
保证金
持仓
强平价
资金费率
标记价格
结算价格
到期日
```

所以交易系统里，合约交易页一定比现货交易页复杂。

## 四、合约规格：期货不是随便写的协议

期货不是双方随便约定一个东西就能在交易所交易。它必须有明确的合约规格 Contract Specifications。

合约规格可以理解为这个合约的“接口定义”。

就像前端调用接口前要知道字段结构：

```ts
interface Order {
  symbol: string;
  price: string;
  amount: string;
  side: "buy" | "sell";
}
```

期货合约也要定义清楚：

```text
标的资产是什么
合约单位是多少
报价单位是什么
最小价格变动是多少
到期月份是什么
交易时间是什么
结算方式是什么
保证金要求是什么
```

比如传统期货里，一个原油期货合约、一份黄金期货合约、一份股指期货合约，它们的合约单位都可能不一样。

Web3 里也有类似概念。

比如 BTC 永续合约或 ETH 永续合约，系统也要定义：

```text
交易对：BTC/USDT
合约面值：一张合约代表多少 BTC
价格精度：最多几位小数
数量精度：最多几位小数
最小下单数量
最大杠杆
保证金资产：USDT / USDC / Coin-M
资金费率结算周期
强平规则
```

所以从开发角度看，合约规格就是交易系统的基础配置。
前端下单表单、价格输入、数量输入、杠杆选择、风险提示，很多都来自合约规格。

---

## 五、交易代码：为什么合约会有代码？

传统期货市场里，一个合约通常有交易代码 Trading Code。

交易代码用于快速表示：

```text
交易品种
到期月份
到期年份
```

比如某个股指期货、原油期货或黄金期货，会用简短代码来表示具体合约。

你可以把它类比成 Web3 里的 symbol。

比如：

```text
BTC/USDT
ETH/USDT
SOL/USDT
BTC-PERP
ETH-20260630
```

现货里 `BTC/USDT` 已经够用了，因为它没有到期日。
但期货通常有不同到期时间，所以需要更完整的合约代码。

例如：

```text
BTC-2026-03
BTC-2026-06
BTC-2026-09
```

这表示不同到期月份的 BTC 期货合约。

永续合约一般没有到期日，所以通常写成：

```text
BTC-PERP
ETH-PERP
```

PERP 就是 Perpetual，表示永续。

从前端角度看，交易代码会影响：

```text
路由参数
行情订阅 topic
下单接口 symbol
K 线接口 symbol
持仓列表 symbol
委托列表 symbol
```

这也是为什么交易系统里经常需要 `parseSymbol`、`symbolToUrlPair`、`toSymbolKey` 这类工具函数。
因为页面展示、接口参数、URL 路由和实时推送 topic 可能使用不同格式。

## 六、到期和结算：传统期货为什么要“结束”？

传统期货通常有到期日 Expiration。

到期后，这个合约不能无限交易下去，需要结算 Settlement。

结算一般分两类：

```text
实物交割
现金结算
```

### 实物交割

实物交割就是到期后真的交付标的资产。

比如商品期货里，理论上可能涉及原油、农产品、金属等实物交付。普通交易者一般不会真的等到交割，而是在到期前平仓。

### 现金结算

现金结算不交付实物，而是根据结算价格计算盈亏，用现金了结。

很多股指期货更接近现金结算。

从 Web3 角度看，你可以这样理解：

```text
传统期货：通常有到期日，到期后要结算
永续合约：没有到期日，通过资金费率维持价格锚定
期权：有到期日，到期后决定是否行权或结算
```

所以永续合约和传统期货最大的不同之一就是：永续合约没有到期日。

那它怎么避免价格长期偏离现货？

靠资金费率 Funding Rate。

如果永续价格明显高于现货，通常多头付钱给空头。
如果永续价格明显低于现货，通常空头付钱给多头。

这个机制相当于用周期性费用，让永续价格尽量贴近现货指数价格。

## 七、Tick：价格不是可以无限细分的

Tick 可以理解为最小价格变动单位。

比如一个合约规定最小价格变动是 0.25。
那价格可以从：

```text
5000.00
```

跳到：

```text
5000.25
5000.50
5000.75
5001.00
```

但不能挂：

```text
5000.13
```

这就是 Tick Size。

Web3 里也有类似概念，只是我们经常叫：

```text
priceScale
pricePrecision
tickSize
```

比如 BTC/USDT 合约价格可能允许 1 位或 2 位小数。
某些低价币可能允许更多小数。

前端开发里，这个字段很重要。

它影响：

```text
价格输入框允许几位小数
限价单价格是否合法
盘口价格如何展示
K 线价格如何格式化
价格加减按钮每次跳多少
```

如果不处理 Tick，用户可能输入一个交易系统不接受的价格。

比如系统只接受：

```text
65000.0
65000.5
65001.0
```

但前端允许用户输入：

```text
65000.37
```

那下单接口就可能报错。

所以交易前端不是简单 input，它要受合约规格约束。

## 八、价格限制：市场不是完全无边界

传统期货市场里可能有价格限制 Futures Price Limits，也就是涨跌停或价格波动限制。

它的作用是防止极端行情下价格瞬间失控。

在 Web3 里，尤其是加密货币市场，很多永续合约没有传统意义上的涨跌停，但依然会有风控限制，例如：

```text
价格保护
最大偏离限制
最小下单价格
最大下单价格
指数价格保护
标记价格保护
最大杠杆限制
最大仓位限制
```

比如用户下限价单时，价格不能偏离当前标记价格太远。
或者市价单执行时，如果滑点过大，系统拒绝成交。

这类限制在前端上会体现为：

```text
下单前校验
风险提示
按钮禁用
接口错误展示
价格范围提示
```

所以价格限制不是“后端的事情”。
前端也应该尽量提前提示，避免用户提交后才看到错误。

## 九、名义价值：为什么仓位看起来比本金大很多？

名义价值 Notional Value，是理解期货和永续合约的关键。

它表示你实际控制的仓位规模。

公式可以简单理解为：

```text
名义价值 = 合约价格 × 合约数量 × 合约乘数
```

Web3 里可以简化为：

```text
名义仓位 = 开仓价格 × 仓位数量
```

比如 BTC 当前价格是 60,000 USDT。
你开了 0.1 BTC 的多仓。

那你的名义仓位约为：

```text
60,000 × 0.1 = 6,000 USDT
```

如果你只用了 600 USDT 保证金，那杠杆大约是：

```text
6,000 / 600 = 10x
```

这就是为什么合约交易里，经常看到“本金不大，但仓位很大”。

名义价值决定了价格波动对你盈亏的影响。

如果 6,000 USDT 仓位上涨 1%，你的盈亏大约是：

```text
6,000 × 1% = 60 USDT
```

而你的保证金只有 600 USDT，所以这相当于保证金收益约 10%。

反过来，亏损也会被放大。

所以杠杆不是免费放大收益，而是同时放大风险。

## 十、保证金：不是买资产的首付款

很多人会把保证金理解成“买资产的首付款”，这是错误的。

期货保证金不是你买了底层资产的一部分付款。
它更像是你为了维持这个合约头寸而存放的履约保证。

Web3 里的永续合约也是一样。

你用 100 USDT 保证金开 1000 USDT 的 BTC 多仓，并不代表你买了 100 USDT 的 BTC，也不代表你拥有 1000 USDT 的 BTC。
你只是用 100 USDT 作为风险抵押，建立了 1000 USDT 名义价值的 BTC 价格仓位。

保证金分几类：

```text
初始保证金：开仓时需要的保证金
维持保证金：维持仓位最低需要的保证金
可用保证金：还可以继续开仓或承担亏损的余额
占用保证金：已经被当前仓位占用的部分
```

前端页面上常见字段：

```text
账户余额
可用保证金
仓位保证金
冻结保证金
保证金率
强平价
```

这些字段都和风控相关。

如果用户亏损越来越大，保证金不足，就可能被强平。

## 十一、逐日盯市：亏损和盈利不是最后才算

传统期货市场有一个重要机制：Mark-to-Market，逐日盯市。

它的意思是：根据每天的结算价，对持仓盈亏进行结算。盈利的一方收到钱，亏损的一方支付钱。

在 Web3 永续合约里，用户更常见的是实时看到：

```text
未实现盈亏
收益率
保证金率
强平价
标记价格
```

虽然具体结算方式和传统期货不同，但思想类似：合约头寸的风险不是到最后才出现，而是在价格变化过程中持续反映。

从前端角度看，这就是为什么持仓表格不能静态展示。

它需要随着行情变化不断更新：

```text
标记价格变化
未实现盈亏变化
收益率变化
强平价风险变化
```

所以合约交易页通常要接实时行情，并且要刷新持仓状态。

## 十二、投机者和套保者：谁在交易期货？

期货市场里有两类非常重要的参与者。

### 套保者 Hedger

套保者使用期货是为了降低风险。

比如：

```text
矿工担心 BTC 下跌，用期货或永续合约对冲未来收入
协议金库持有大量 ETH，用衍生品降低价格波动风险
做市商用期货对冲现货库存风险
```

他们不是单纯为了赌涨跌，而是为了管理已有风险。

### 投机者 Speculator

投机者主动承担价格风险，希望从价格波动中获利。

比如：

```text
认为 BTC 会涨，开多 BTC 永续
认为 ETH 会跌，开空 ETH 永续
基于宏观消息交易指数期货
基于链上数据交易加密资产合约
```

投机者承担风险，同时也为市场提供流动性。

在 Web3 交易平台里，C 端用户大多更接近投机者。
但做市商、机构、矿工、协议金库，则可能更接近套保者。

## 十三、期货、永续合约和期权的关系

你可以把它们放在一个框架里理解。

### 期货 Futures

```text
有到期日
有标准化合约
通过保证金交易
可以做多或做空
到期需要结算
```

### 永续合约 Perpetual

```text
没有到期日
像期货一样用保证金和杠杆交易
通过资金费率让价格贴近现货
在 Web3 交易平台里非常常见
```

### 期权 Options

```text
交易的是未来买入或卖出的权利
有行权价
有到期日
买方支付权利金
Call 看涨，Put 看跌
```

如果你是 Web3 前端开发者，可以先按这个顺序理解：

```text
现货：买卖资产本身
期货：交易未来价格风险
永续：没有到期日的期货式合约
期权：交易未来选择权
```

它不是单纯 CRUD，而是金融业务状态的组合。

## 十五、一个 Web3 开发者应该重点掌握什么？

如果你不是交易员，而是 Web3 前端或全栈开发者，你不需要一开始就研究复杂定价模型。

你更应该优先掌握这几类知识。

### 第一类：交易对象

```text
现货
期货
永续合约
期权
```

你要知道用户到底在买卖什么。

### 第二类：订单机制

```text
限价单
市价单
计划委托
止盈止损
撤单
成交
部分成交
```

你要知道订单生命周期怎么变化。

### 第三类：风险字段

```text
杠杆
保证金
名义价值
强平价
资金费率
标记价格
指数价格
```

你要知道为什么页面要展示这些字段。

### 第四类：前端数据联动

```text
下单后刷新余额
下单后刷新当前委托
成交后刷新持仓
平仓后刷新历史委托
撤单后释放冻结保证金
切换 symbol 后重新订阅行情
```

你要知道一个操作会影响哪些状态。

## 十六、最后总结

期货的本质，不是“买一个东西”，而是交易未来价格风险。

它通过标准化合约，把标的资产、合约单位、价格最小变动、到期结算、保证金、名义价值和风控规则固定下来，让不同市场参与者可以用它来投机、套保和管理风险。

放到 Web3 语境里，永续合约是期货思想的一种重要变体：

```text
传统期货：有到期日，需要结算
永续合约：没有到期日，用资金费率维持价格锚定
```

对于 Web3 从业者来说，理解期货最大的价值不是让你去交易，而是让你更理解交易系统：

```text
为什么合约需要保证金；
为什么下单要区分开多开空；
为什么要有强平价；
为什么要有标记价格；
为什么要有资金费率；
为什么交易前端要处理精度、杠杆、风控和订单状态；
为什么下单成功后不能只 toast，而要刷新余额、持仓和委托。
```

一句话总结：

**期货是一种围绕未来价格风险设计的标准化合约；而 Web3 里的永续合约，就是把这种合约交易思想放进加密资产市场，并用资金费率、保证金、标记价格和强平机制持续运行起来。**
