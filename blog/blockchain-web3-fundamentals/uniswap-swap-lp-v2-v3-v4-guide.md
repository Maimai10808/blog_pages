# Uniswap 全面指南：从 Swap 到 LP 做市，如何理解 v2、v3 和 v4？

Uniswap 是 DeFi 里最重要的去中心化交易协议之一。

很多人第一次接触 Uniswap，只知道它可以 swap，也就是把一种 token 换成另一种 token。

但实际上，Uniswap 不只是一个交易页面。

它同时也是：

```txt
去中心化交易所 DEX
自动做市商 AMM
流动性提供平台
DeFi 数据分析入口
钱包和 API 基础设施
Layer2 / DeFi 链生态入口
```text

用户在 Uniswap 上主要可以做两件事：

```txt
交易 token
提供流动性，赚取交易手续费
```

对 Web3 前端开发者来说，理解 Uniswap 不仅是理解一个产品，更是在理解 DEX、AMM、LP、滑点、路由、流动性池、价格区间、手续费和无常损失这些核心概念。

---

## 一、Uniswap 到底是什么？

Uniswap 本质上是一个去中心化交易协议。

它允许用户在链上直接交换 token，而不需要依赖中心化交易所。

在中心化交易所中，交易通常依赖订单簿。

买方挂买单，卖方挂卖单，系统撮合成交。

而 Uniswap 使用的是 AMM，也就是自动做市商模型。

用户不是和另一个用户直接成交，而是和流动性池成交。

流动性池里的资产由 LP，也就是 liquidity provider 提供。

所以 Uniswap 的核心可以概括为：

```txt
交易者使用池子交易。
LP 提供池子流动性。
协议根据池子价格和路由完成兑换。
```text

Uniswap 的 Trade 区主要用于交易 token。

常见功能包括：

```txt
Swap
Limit
Buy
Sell
```text

其中最核心的是 Swap。

## 四、Swap：最基础的兑换

Swap 就是把一种资产换成另一种资产。

例如用户选择：

```txt
输入：1 ETH
输出：USDC
```

Uniswap 会根据当前池子流动性、路由和价格，计算用户大概能拿到多少 USDC。

例如：

```txt
1 ETH -> 1972 USDC
```text

在 swap 页面里，通常会看到几个重要信息：

```txt
预估输出数量
交易手续费
网络费用
交易路由
价格影响
最大滑点
最低接收量
交易截止时间
```

这些信息都非常重要。

因为它们决定了这笔交易是否划算、是否安全，以及最终能不能成功执行。

---

## 五、Route：交易路由是什么？

当用户用 ETH 换 USDC 时，并不一定是直接走 ETH / USDC 池子。

Uniswap 可能会选择一条更优路径。

例如：

```txt
ETH -> WETH -> USDT -> USDC
```text

为什么要绕这么多步？

因为某些路径的流动性更好，最终价格更优，滑点更低。

所以路由的目标是：

```txt
帮用户找到更好的成交结果。
```

在 Uniswap 中，路由可能来自：

```txt
Uniswap v2 池子
Uniswap v3 池子
Uniswap v4 池子
UniswapX
v4 hook pools
其他流动性路径
```text

普通用户通常不需要手动选择路由，保持默认即可。

前端和路由系统会自动帮用户寻找更优路径。

---

## 六、Price Impact：价格影响

价格影响指的是：

```txt
你的这笔交易本身对池子价格造成了多大冲击。
```

在 AMM 中，池子价格由池子中两种资产的比例决定。

如果你交易量很大，就会明显改变池子资产比例，从而推动价格变化。

这就是价格影响。

例如一个池子很浅，你拿很多 ETH 去换 USDC，就会把池子里的 USDC 大量买走，导致成交价格变差。

价格影响越大，说明你的交易对市场价格冲击越大。

一般来说：

```txt
池子越深，价格影响越小。
交易越大，价格影响越大。
```text

---

## 七、Max Slippage：最大滑点

最大滑点是用户愿意接受的最大价格偏差。

比如系统预估你可以收到：

```txt
1972 USDC
```

如果最大滑点设置为 1%，那最低接收量可能是：

```txt
1953 USDC
```text

这意味着：

```txt
如果最终输出低于 1953 USDC，交易就会失败。
```

最大滑点的作用是保护用户。

因为从你点击确认到交易真正上链，中间会有时间差。

在这段时间里，池子价格可能发生变化。

如果没有最低接收量保护，用户可能会在非常差的价格下成交。

所以滑点不是简单的 UI 展示，而是会进入链上交易参数。

在 swap 交易里，经常对应：

```txt
amountOutMinimum
```text

---

## 八、Swap Deadline：交易截止时间

Swap Deadline 表示这笔交易必须在某个时间之前执行。

例如默认 30 分钟。

如果超过这个时间还没有执行，交易就会失效。

它的作用是防止一笔旧交易在很久之后被执行。

在正常情况下，用户不需要手动调太多。

如果网络非常拥堵，deadline 太短可能导致交易失败。

如果 deadline 太长，旧交易被执行的风险会增加。

所以一般用户保持默认即可。

---

## 九、Limit：限价交易

Limit 功能类似传统交易所里的限价单。

用户可以设置：

```txt
当 ETH 到某个价格时，再执行交易。
```

例如：

```txt
当 1 ETH = 2200 USDC 时，卖出 1 ETH。
```text

和普通 swap 不同，swap 是按当前价格立即交易。

limit 是设置目标价格，等市场价格达到条件后再成交。

可以理解为：

```txt
Swap：现在成交。
Limit：到指定价格再成交。
```

Limit 更适合有明确买入价或卖出价的用户。

## 十一、Pool：流动性池区

Pool 是 Uniswap 中非常重要的模块。

用户可以在这里：

```txt
创建新的流动性池
给已有池子提供流动性
管理自己的 LP 仓位
赚取交易手续费
```text

提供流动性就是把两种资产放进池子里，让别人可以通过这个池子交易。

交易者每次 swap 都会支付手续费。

这些手续费会分给 LP。

所以 LP 的收益来源主要是：

```txt
交易手续费
```

但 LP 同时也要承担风险，比如：

```txt
无常损失
价格波动
区间失效
手续费不足以覆盖损失
智能合约风险
```text

## 十二、选择 v2、v3 还是 v4？

在创建或提供流动性时，用户可能需要选择：

```txt
Uniswap v2
Uniswap v3
Uniswap v4
```

很多人会直觉认为：

```txt
v4 最新，所以一定最好。
```text

但真实情况不一定。

不同版本适合不同策略。

### v2

v2 更简单。

LP 的流动性覆盖整个价格区间：

```txt
0 到 ∞
```

它适合不想主动管理价格区间的用户。

但资本效率较低。

### v3

v3 引入集中流动性。

LP 可以选择一个价格区间。

如果价格在区间内，LP 赚手续费。

如果价格跑出区间，LP 不再赚手续费。

v3 的资本效率更高，但管理难度也更高。

### v4

v4 在 v3 的基础上引入更灵活的架构，例如 hooks。

hooks 可以让开发者在池子的生命周期中插入自定义逻辑。

例如：

```txt
动态手续费
自定义订单逻辑
特殊费用模型
自动再平衡
限价类功能
新的 AMM 行为
```text

v4 更灵活，但对普通 LP 来说，也更需要理解具体池子的设计。

所以选择哪个版本，不是看哪个最新，而是看：

```txt
哪个池子的流动性更好？
哪个费率更适合？
哪个版本交易量更高？
哪个策略更适合自己？
哪个池子的风险自己能理解？
```

---

## 十三、选择交易对

提供流动性时，第一步通常是选择交易对。

例如：

```txt
ETH / USDC
ETH / WBTC
ETH / UNI
ETH / 某个新项目 token
```text

选择交易对时，要考虑：

```txt
资产是否愿意长期持有
两个资产价格相关性如何
交易量是否足够
TVL 是否足够
手续费收入是否稳定
波动是否太大
是否容易出现无常损失
```

比如 ETH / USDC 比较常见，但会暴露在 ETH 单边波动风险中。

ETH / WBTC 两个资产相关性可能更高，但仍然会有相对价格变化。

长尾 token / ETH 可能手续费很高，但风险也大。

---

## 十四、Fee Tier：手续费档位

Uniswap v3 和 v4 中，很多池子会有不同手续费档位。

常见档位包括：

```txt
0.01%
0.05%
0.3%
1%
```text

不同费率适合不同资产。

一般来说：

```txt
稳定币 / 稳定币：低费率
主流资产 / 主流资产：中等费率
长尾资产 / 高波动资产：高费率
```

手续费越高，不一定收益越好。

因为交易者可能会被路由到更便宜、更深的池子。

真正要看的是：

```txt
这个池子有没有交易量？
交易量和 TVL 的比例高不高？
LP 实际能分到多少手续费？
```text

这也是为什么选择池子时不能只看 APR。

---

## 十五、TVL：池子里有多少钱

TVL 是 Total Value Locked，也就是池子中锁定的总资产价值。

TVL 越高，说明池子流动性越深。

流动性深的好处是：

```txt
交易滑点低
更容易被路由系统选择
大额交易更容易成交
池子更稳定
```

但 TVL 高不一定代表 LP 收益高。

因为手续费要在所有 LP 之间分配。

如果一个池子 TVL 很高，但交易量不高，那么 APR 可能并不高。

所以更重要的是看：

```txt
交易量 / TVL
手续费 / TVL
```text

---

## 十六、价格区间：v3/v4 LP 的核心

在 Uniswap v3/v4 中，提供流动性最关键的一步是设置价格区间。

例如 ETH / USDC 当前价格是 2000。

你可以设置区间：

```txt
1811 - 2130 USDC per ETH
```

这表示：

```txt
只有当 ETH 价格在这个区间内时，你的流动性才会参与交易并赚手续费。
```text

如果价格低于 1811 或高于 2130，你的仓位就会出区间。

出区间后：

```txt
不再赚手续费
仓位会变成单一资产
需要等待价格回来或主动调整区间
```

所以价格区间决定了：

```txt
资金效率
手续费收益
出区间概率
无常损失风险
管理频率
```text

---

## 十七、价格区间不是永远看美元价格

很多新手会误以为价格区间永远是美元价格。

比如 ETH / USDC 里，价格显示为：

```txt
2000 USDC per ETH
```

因为 USDC 约等于 1 美元，所以它看起来像美元价格。

但如果交易对是：

```txt
WBTC / ETH
```text

那价格就不是美元。

而是：

```txt
多少 ETH 可以换 1 WBTC
```

所以设置价格区间时，要看清楚报价单位。

本质上，Uniswap 里的价格永远是：

```txt
一种资产相对于另一种资产的比例。
```text

前端展示时需要特别注意 token0 / token1 的方向，以及是否提供反转价格显示。

---

## 十八、为什么输入一种资产后，另一种资产会自动变化？

在 v3/v4 中，LP 输入一种资产数量后，系统会自动计算另一种资产需要多少。

这个比例取决于你选择的价格区间和当前价格位置。

如果你的区间围绕当前价格，通常需要两种资产。

如果你的区间完全在当前价格上方或下方，可能只需要一种资产。

例如在 ETH / USDC 池中：

- 区间在当前价格附近：需要 ETH + USDC；
- 区间完全高于当前价格：可能主要需要 ETH；
- 区间完全低于当前价格：可能主要需要 USDC。

这也是 v3/v4 能实现类似区间限价单效果的原因。

## 二十五、LP 策略：不能只看 APR

很多人选择 LP 池子时，只看 APR。

但这是不够的。

因为 APR 只是一个结果指标，而且经常会波动。

更重要的是分析 APR 背后的来源。

你至少要看：

```txt
TVL
交易量
手续费收入
费用 / TVL 比例
资产相关性
价格波动率
流动性分布
当前价格位置
是否容易出区间
无常损失风险
```

一个高 APR 池子可能很诱人，但如果资产波动很大，或者价格很快跑出区间，实际收益可能并不好。

---

## 二十六、如何筛选流动性池？

一种常见思路是先过滤掉低质量池子。

比如：

```txt
只看主流链
只看某个核心资产相关池子
只看 TVL 大于一定规模的池子
只看交易量稳定的池子
只看手续费 / TVL 较高的池子
```text

其中，手续费 / TVL 是一个很有用的指标。

它大致反映：

```txt
池子里的每一单位资金，能产生多少手续费。
```

如果一个池子 TVL 很高，但手续费很低，LP 收益可能一般。

如果一个池子 TVL 不算特别高，但交易频繁，手续费 / TVL 可能更好。

不过这个指标也不能孤立看。

还要看交易量是否稳定、资产价格是否剧烈波动、是否存在刷量或短期异常。

---

## 二十七、为什么要看时间窗口？

分析池子时，不要只看一天的数据。

一天的数据可能受短期事件影响很大。

比如：

```txt
某个 token 突然暴涨
某个新闻带来短期交易量
某个大户临时交易
市场短期波动
```text

所以很多人会看 7 天、14 天、30 天平均数据。

例如使用过去 14 天计算：

```txt
平均每日交易量
平均每日手续费
平均 APR
价格波动率
相关性
```

这样可以减少短期噪音。

但也要注意，如果市场环境已经明显变化，过去 14 天的数据也不一定能代表未来。

---

## 二十八、选择价格区间时要看什么？

设置价格区间时，不能只凭感觉。

你需要考虑：

```txt
当前价格
历史价格区间
近期高低点
波动率
资产相关性
支撑位和压力位
流动性集中在哪里
自己能接受多久调整一次
自己是否愿意持有出区间后的单边资产
```text

区间越窄：

```txt
资本效率越高
潜在手续费 APR 越高
越容易出区间
管理频率越高
```

区间越宽：

```txt
更不容易出区间
管理压力更低
资本效率下降
收益可能更接近 v2
```text

所以没有绝对正确的区间。

只有适合你风险偏好和管理能力的区间。

---

## 二十九、如何理解流动性分布？

在 Uniswap v3/v4 中，流动性不是均匀分布的。

不同价格区间里，可能有不同数量的资金。

前端图表中经常会展示：

```txt
当前价格附近有多少流动性
上方价格区间有多少流动性
下方价格区间有多少流动性
其他 LP 把钱放在哪里
```

这很重要。

因为你的收益取决于你所在区间的交易量和竞争程度。

如果某个价格区间流动性很多，说明很多 LP 都在那里竞争手续费。

如果某个区间交易活跃但流动性少，潜在 APR 可能更高，但风险也可能更高。

---

## 三十、无常损失和机会成本

LP 最大的风险之一是无常损失。

无常损失本质上是：

```txt
提供流动性后的资产价值，
相比单纯持有两种资产，
产生了差异。
```text

比如你把 ETH 和某个 token 放进池子。

如果其中一个资产大涨，AMM 会自动帮你卖出上涨资产、买入相对下跌资产。

这会导致你相比单纯持有，可能少赚一部分。

在 v3/v4 中，区间越窄，这种资产转换越明显。

所以很多时候，LP 赚到的手续费要和无常损失比较。

关键问题是：

```txt
手续费收益能不能覆盖无常损失？
```

如果不能，表面 APR 很高，实际可能不划算。

---

## 三十一、Profit vs HODL：和持有相比是否真的赚了？

做 LP 时，不能只看池子里的绝对余额变化。

还要比较：

```txt
如果我当初什么都不做，只是持有这些资产，现在会是多少？
```text

这就是 Profit vs HODL 的思路。

例如你一开始投入：

```txt
20% ETH
80% 某个 token
```

现在 LP 仓位价值下降了，但你赚了一些手续费。

你需要计算：

```txt
当前 LP 价值 + 已赚手续费
```text

然后和下面几种情况比较：

```txt
继续持有原始比例资产
全部持有 ETH
全部持有另一个 token
保持 50/50
```

这样才能判断 LP 策略是否真的优于单纯持有。

很多时候，LP 看起来赚了手续费，但和 HODL 相比可能并没有跑赢。

---

## 三十二、跟踪 LP 仓位时要看哪些指标？

进入 LP 仓位后，不是放着不管。

你应该持续跟踪：

```txt
当前价格是否在区间内
已赚手续费
未领取手续费
已领取手续费
当前资产组成
相对 HODL 盈亏
无常损失
手续费覆盖率
APR
区间内停留时间
价格是否接近边界
是否需要再平衡
```text

特别是 v3/v4 区间流动性，如果价格快要出区间，需要提前考虑：

```txt
是否调整区间？
是否撤出？
是否继续等待？
是否对冲？
```

一些工具还可以设置价格提醒，帮助 LP 在接近区间边界时及时处理。

## 三十四、Uniswap v2、v3、v4 的简要对比

| 版本 | 核心特点              | LP 体验                  | 适合场景                           |
| ---- | --------------------- | ------------------------ | ---------------------------------- |
| v2   | 全区间 AMM，x\*y=k    | 简单、被动               | 普通流动性池、长尾资产基础交易     |
| v3   | 集中流动性，区间做市  | 资本效率高，但需要管理   | 主流资产、高交易量池、专业 LP      |
| v4   | hooks、更灵活池子架构 | 策略空间更大，复杂度更高 | 自定义 AMM、动态费率、特殊交易逻辑 |

可以简单记：

```txt
v2：简单 AMM。
v3：集中流动性。
v4：可编程池子。
```text

## 三十五、面试回答参考

如果面试官问：“Uniswap 是什么？v2、v3、v4 有什么区别？”

可以这样回答：

Uniswap 是以太坊生态中最重要的去中心化交易协议之一，本质上是一个基于 AMM 的 DEX。用户可以在上面 swap token，也可以作为 LP 提供流动性，赚取交易手续费。

Uniswap v2 使用经典的常数乘积模型，LP 的资金覆盖从 0 到无限大的整个价格区间。它的优点是简单、被动，但缺点是资本效率低。

Uniswap v3 引入集中流动性，允许 LP 自己选择价格区间。只要价格在区间内，流动性就是活跃的，可以赚手续费；如果价格跑出区间，就不再赚手续费，仓位也会变成单边资产。v3 大幅提高了资本效率，但也提高了 LP 管理难度。

Uniswap v4 在 v3 的基础上引入 hooks，使池子逻辑更可编程，比如动态手续费、自定义交易逻辑、自动化策略等。v4 的灵活性更强，但对用户和开发者理解成本也更高。

从前端角度看，Uniswap 涉及报价、路由、滑点、deadline、approve、swap、LP NFT、价格区间、tick、手续费和仓位管理等一整套 Web3 交易交互，是理解 DeFi 前端非常好的案例。

## 三十六、总结

Uniswap 不只是一个 swap 工具。

它是一套完整的 DeFi 交易和流动性基础设施。

用户可以通过它：

```txt
交换 token
设置限价单
法币买卖 crypto
提供流动性
管理 LP 仓位
查看 token 和池子数据
接入 UniswapX、API 和 Unichain 生态
```

但如果你想成为 LP，就不能只看表面 APR。

你需要理解：

```txt
TVL
交易量
手续费 / TVL
价格区间
流动性分布
无常损失
Profit vs HODL
区间内停留时间
版本差异
费用档位
资产相关性
```text

Uniswap v2 更简单，适合被动流动性。

Uniswap v3 提高资本效率，但需要主动管理。

Uniswap v4 引入 hooks，让池子逻辑更加可编程。

所以，真正理解 Uniswap，不只是知道怎么点 swap，而是理解它背后的 AMM 机制、LP 收益来源、风险结构和前端交互逻辑。

对于 Web3 前端开发者来说，Uniswap 是一个非常值得深入拆解的产品。

因为它几乎包含了 DeFi 前端最核心的一整套能力：

```txt
链上交易构造
报价和路由
滑点保护
LP 仓位管理
数据分析
风险提示
收益追踪
多版本协议适配
```

能把这些讲清楚，基本就已经具备了比较扎实的 DeFi 前端理解。
