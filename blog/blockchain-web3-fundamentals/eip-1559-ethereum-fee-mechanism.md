# EIP-1559 详解：Ethereum 手续费机制如何从 Gas Price 走向 Base Fee

在 Ethereum 早期的手续费模型中，用户发送交易时需要自己设置一个 `gas price`。

这个机制看似简单，但在网络拥堵时会带来很多问题：用户不知道该出多少钱，钱包估算经常不准确，很多人为了尽快上链会多付手续费，而交易仍然可能因为估价不足长时间卡在交易池中。

EIP-1559 正是为了解决这些问题而提出的。它改变了 Ethereum 的手续费市场，引入了 Base Fee、Tip、Fee Cap 和手续费销毁机制，让交易费用更加可预测，也让 ETH 供应与网络使用量之间产生了新的联系。

这篇文章会系统梳理 EIP-1559 的背景、核心机制和常见误区。

## 一、什么是 EIP

EIP 的全称是 Ethereum Improvement Proposal，也就是 Ethereum 改进提案。

它是 Ethereum 社区提出、讨论和规范协议改动的主要方式。

EIP 机制借鉴了 Bitcoin Improvement Proposal，也就是 BIP，而 BIP 又受到 Python Improvement Proposal 的影响。

简单来说，任何人都可以通过 EIP 提出对 Ethereum 的改进建议。

这些建议可能涉及：

共识层规则；

网络协议；

客户端接口；

应用层标准；

开发流程；

信息说明。

EIP-1 定义了 EIP 的基本流程和规范。

## 二、EIP 的几种类型

EIP 可以分成不同类型，其中最重要的是 Core EIP。

### 1. Core EIP

Core EIP 会改变 Ethereum 协议本身，尤其是共识规则。

这类 EIP 需要所有客户端在同一个网络升级中同时支持，否则网络可能分叉。

因此，Core EIP 通常需要通过硬分叉，也就是 network upgrade，才能正式部署。

EIP-1559 就属于 Core EIP。

因为它改变了交易费用模型、区块头字段和交易处理逻辑。

### 2. Networking EIP

Networking EIP 主要影响节点之间的通信协议。

例如：

devp2p；

轻客户端协议；

节点发现；

网络消息格式。

### 3. Interface EIP

Interface EIP 主要影响 Ethereum 的接口层。

例如：

JSON-RPC API；

合约 ABI；

客户端接口规范。

### 4. ERC

ERC 是 Ethereum Request for Comments，主要用于应用层标准。

最常见的例子是：

ERC-20；

ERC-721；

ERC-1155。

ERC-20 定义了同质化代币标准，ERC-721 定义了非同质化代币标准。

它们不要求整个网络硬分叉升级，而是给应用开发者提供统一约定。

### 5. Meta EIP 和 Informational EIP

Meta EIP 通常用于描述流程、网络升级包或多个 EIP 的组合。

Informational EIP 则更多用于发布信息、设计说明或规范性文档。

## 三、EIP-1559 想解决什么问题

EIP-1559 主要有三个目标。

第一，让交易费用更可预测。

第二，减少交易被延迟打包的情况。

第三，让 Ethereum 网络使用量和 ETH 供应产生反馈关系。

这三个目标分别对应 EIP-1559 的几个核心机制：

Base Fee；

可变区块大小；

Tip 和 Fee Cap；

Base Fee 销毁。

## 四、旧手续费模型的问题：第一价格拍卖

在 EIP-1559 之前，Ethereum 使用的是第一价格拍卖机制。

用户给交易设置一个 gas price。

矿工通常会优先打包 gas price 更高的交易。

问题是，用户并不知道自己到底应该出多少钱。

假设当前区块中最高需要 100 gwei 就能被打包，但你以为需要 120 gwei，于是设置了 120 gwei。

最后你的交易确实被打包了，但你实际上多付了 20 gwei。

在网络拥堵时，这种过度出价非常常见。

用户为了避免交易卡住，往往会设置更高 gas price，导致整体费用体验很差。

这就是 EIP-1559 想改善的第一个问题：手续费估算困难和过度支付。

## 五、Base Fee：每个区块的最低手续费

EIP-1559 引入了 Base Fee。

Base Fee 是交易进入某个区块所必须支付的最低基础费用。

它被写入区块头中。

也就是说，用户和钱包可以直接看到当前区块的 Base Fee，并根据规则预测下一个区块的 Base Fee。

这让手续费估算变得更容易。

在 EIP-1559 之后，用户不再需要盲猜当前市场中其他人愿意付多少 gas price，而是可以知道：

```txt
当前网络最低需要支付多少基础费用。
```

如果交易愿意支付的费用低于 Base Fee，就不会被当前区块包含。

如果足够高，就具备被打包的基本条件。

## 六、Base Fee 会如何变化

Base Fee 不是固定的。

它会根据上一个区块的 gas 使用情况自动调整。

EIP-1559 希望区块长期维持在目标使用率附近。

如果上一个区块超过目标使用量，说明需求较高，Base Fee 会上升。

如果上一个区块低于目标使用量，说明需求较低，Base Fee 会下降。

这有点类似“拥堵定价”：

网络越拥堵，Base Fee 越高；

网络越空闲，Base Fee 越低。

EIP-1559 中，Base Fee 每个区块最多变化 12.5%。

如果连续多个区块都很满，Base Fee 会快速上升。

如果需求下降，Base Fee 也会逐步回落。

## 七、可变区块大小：为什么区块可以临时变大

EIP-1559 还引入了可变区块大小。

简单理解是：区块有一个目标大小，也有一个最大大小。

例如可以把目标理解为 50% 满，而最大容量是目标的两倍。

在正常情况下，EIP-1559 希望区块保持在目标大小附近。

当短时间内需求突然增加时，区块可以临时变大，容纳更多交易。

这可以减少交易在 mempool 中等待的时间。

但如果区块持续超过目标大小，Base Fee 会快速上升，直到部分用户不愿继续支付这么高的费用，需求下降，区块重新回到目标容量附近。

所以，可变区块大小并不是永久提高吞吐量，而是提供短期弹性。

## 八、EIP-1559 不是单纯扩容方案

很多人会误以为 EIP-1559 让区块变大，所以它能大幅降低 Gas 费。

这个理解不准确。

EIP-1559 的可变区块大小主要是为了吸收短期需求波动，让用户更容易进入下一个区块，而不是永久增加区块空间供应。

长期来看，Ethereum 的平均手续费仍然取决于供需关系。

如果需求远大于区块空间，费用仍然会很高。

真正大幅降低用户成本的方案，更多依赖：

Layer 2；

Rollup；

Danksharding；

更高效的执行和数据可用性方案。

EIP-1559 改善的是费用市场机制，而不是从根本上解决扩容问题。

## 九、Fee Cap：用户最多愿意付多少

EIP-1559 用新的参数替代了旧的 gas price 模型。

其中一个重要参数是 Fee Cap，也就是用户愿意为交易支付的最高费用上限。

它表示：

```txt
这笔交易每单位 gas 最多愿意支付多少。
```

用户设置 Fee Cap 后，即使 Base Fee 波动，也不会超过这个上限。

如果实际费用低于 Fee Cap，多出来的部分会退还给用户。

这和旧模型不同。

旧模型中，用户设置多少 gas price，通常就会按这个价格支付。

EIP-1559 中，用户可以设置一个较高 Fee Cap，作为防止 Base Fee 上涨的缓冲，但最终只支付实际需要的费用。

## 十、Tip：给验证者的优先费

Base Fee 会被销毁，不会给区块生产者。

但区块生产者仍然需要有动力打包交易。

因此，EIP-1559 引入了 Tip，也常被称为 Priority Fee。

Tip 是用户额外支付给区块生产者的费用。

在 PoW 时代，它给矿工。

在 PoS 时代，它给验证者或区块提议者。

Tip 有两个主要作用。

第一，激励区块生产者打包交易，而不是打空区块。

第二，在网络极度拥堵时，用户可以通过更高 Tip 表示希望交易更快被打包。

例如，DeFi 套利交易可能有很高的机会成本。如果晚一个区块，套利机会就没了。这类交易愿意支付更高 Tip，以提高优先级。

## 十一、EIP-1559 交易实际怎么收费

一笔 EIP-1559 交易中，用户会设置：

Fee Cap；

Tip。

区块中有：

Base Fee。

实际支付逻辑可以理解为：

```txt
用户最多支付 Fee Cap
其中 Base Fee 被销毁
Tip 支付给区块生产者
剩余部分退还给用户
```

例如：

```txt
Fee Cap = 100 gwei
Base Fee = 60 gwei
Tip = 2 gwei
```

那么用户实际支付：

```txt
60 + 2 = 62 gwei
```

剩下：

```txt
100 - 62 = 38 gwei
```

不会被收走，而是退回给用户。

这就是 EIP-1559 对用户体验的重要改善：用户可以设置较高上限来保证交易有足够空间被打包，但不会因为估高了就全部支付出去。

## 十二、Legacy Transaction 如何兼容

EIP-1559 并没有立即废弃旧交易格式。

旧的 legacy transaction 仍然可以被处理。

它们可以被映射成类似 EIP-1559 的交易：

```txt
Fee Cap = 原 gas price
Tip = gas price - Base Fee
```

这样做的好处是，旧钱包、旧服务、旧工具不需要立刻全部迁移，也仍然可以正常发送交易。

不过 legacy transaction 没有 EIP-1559 原生交易那样清晰的 Fee Cap / Tip 结构，也无法享受同样精确的费用控制体验。

## 十三、为什么 Base Fee 要被销毁

EIP-1559 中最有争议、也最重要的设计之一，是 Base Fee 销毁。

为什么不把 Base Fee 直接给矿工或验证者？

原因是，如果区块生产者能拿到 Base Fee，他们就有动机操纵 Base Fee，让它尽可能高。

EIP-1559 希望 Base Fee 反映真实网络需求，而不是被区块生产者人为影响。

把 Base Fee 销毁，可以让区块生产者对 Base Fee 高低相对中立。

他们主要获得：

区块奖励；

Tip。

这样 Base Fee 更像一种协议层的拥堵价格信号，而不是区块生产者的直接收入来源。

## 十四、Base Fee 销毁带来了什么影响

因为每笔交易都会销毁 Base Fee，所以网络使用越多，销毁的 ETH 就越多。

当区块空间需求上升时：

Base Fee 上升；

每笔交易销毁更多 ETH；

总销毁量增加。

这使得 Ethereum 网络使用量和 ETH 供应之间产生了反馈关系。

可以理解为：

```txt
越多人使用 Ethereum，越多 ETH 被销毁。
```

这对 ETH 的货币政策产生了重要影响。

它相当于把一部分网络手续费从区块生产者收入中移除，并以销毁的方式让所有 ETH 持有人间接受益，因为总供应相对减少。

## 十五、EIP-1559 会让 ETH 一定通缩吗

不一定。

这是一个常见误区。

EIP-1559 会销毁 ETH，但 ETH 是否通缩，取决于：

销毁量是否大于新增发行量。

如果 Base Fee 销毁的 ETH 长期高于区块奖励或 PoS 发行量，那么 ETH 供应可能下降。

如果销毁量低于新增发行量，那么 ETH 仍然是净增发，只是增发速度变慢。

所以不能简单说：

```txt
EIP-1559 = ETH 一定通缩
```

更准确地说：

```txt
EIP-1559 引入了一个与网络使用量相关的 ETH 销毁机制。
```

当网络使用强劲、Base Fee 较高时，销毁量可能非常大。

当网络需求较低、Base Fee 较低时，销毁量也会下降。

## 十六、EIP-1559 会大幅降低 Gas 费吗

也不一定。

EIP-1559 可以降低过度支付，改善费用估算，让交易费用更可预测。

但它不会从根本上降低区块空间的市场价格。

Gas 费本质上取决于：

区块空间供应；

用户需求。

如果很多人同时使用 Ethereum，而区块空间有限，费用仍然会高。

EIP-1559 让用户更少“猜错价格”，但不会凭空创造大量区块空间。

所以它可以让手续费体验更好，但不是大规模扩容方案。

## 十七、EIP-1559 对矿工或验证者有什么影响

在 EIP-1559 中，Base Fee 被销毁，区块生产者不能获得这部分费用。

这看起来像是减少了矿工或验证者收入。

但他们仍然可以获得：

区块奖励；

Tip；

MEV 相关收入。

在某些高价值交易场景中，用户仍然愿意支付很高 Tip，以保证交易优先打包。

例如：

套利；

清算；

NFT mint；

抢购；

高机会成本 DeFi 操作。

因此，EIP-1559 确实改变了费用分配结构，但并不是完全取消区块生产者的手续费收入。

## 十八、EIP-1559 的用户体验改进

对普通用户来说，EIP-1559 最大的好处是手续费更容易理解。

过去钱包要估算一个 gas price，用户也不知道这个价格是否合理。

现在钱包可以根据当前 Base Fee 计算：

建议 Fee Cap；

建议 Priority Fee；

预计最大支付；

预计实际支付。

用户不再需要完全依赖猜测。

并且，因为区块有短期弹性，很多时候交易更容易进入下一个区块，减少长时间卡在交易池中的情况。

这对普通用户体验非常重要。

## 十九、EIP-1559 的协议设计逻辑

可以把 EIP-1559 理解成三个机制共同工作。

### 1. Base Fee

提供协议层的最低费用信号。

### 2. 可变区块大小

提供短期容量弹性，缓解瞬时拥堵。

### 3. Fee Burn

防止区块生产者操纵 Base Fee，并把网络使用与 ETH 供应联系起来。

这三个机制共同改变了 Ethereum 的费用市场。

它不是简单地“降低手续费”，而是重新设计了手续费如何被发现、支付、分配和销毁。

## 二十、一个简单例子

假设当前区块 Base Fee 是 50 gwei。

用户发送交易，设置：

```txt
Fee Cap = 100 gwei
Tip = 2 gwei
```

如果下一块 Base Fee 是 55 gwei，那么交易可以被打包。

用户实际支付：

```txt
55 + 2 = 57 gwei
```

其中：

55 gwei 被销毁；

2 gwei 给区块生产者；

剩余 43 gwei 不会被扣除。

如果 Base Fee 突然涨到 110 gwei，那么这笔交易的 Fee Cap 不够，交易不会被当前区块打包，需要等待 Base Fee 降低或用户提高 Fee Cap。

## 二十一、EIP-1559 的常见误区总结

### 误区一：EIP-1559 会让 Gas 费暴跌

不准确。

它改善费用估算和减少过度支付，但不解决长期区块空间不足问题。

### 误区二：EIP-1559 会让 ETH 一定通缩

不准确。

它引入销毁机制，但是否通缩取决于销毁量和发行量之间的关系。

### 误区三：矿工或验证者完全拿不到手续费

不准确。

Base Fee 被销毁，但 Tip 仍然归区块生产者。

### 误区四：区块大小翻倍就是永久扩容

不准确。

EIP-1559 引入的是弹性区块，目标仍是让区块长期保持在目标容量附近。

### 误区五：用户设置高 Fee Cap 就一定会全部支付

不准确。

Fee Cap 是最高愿付上限，实际费用多余部分会退还。

## 二十二、为什么 EIP-1559 重要

EIP-1559 重要，不只是因为它改变了手续费界面。

它更深层地改变了 Ethereum 的经济结构。

它让手续费市场从完全由用户猜测和矿工选择，转向协议层提供基础价格信号。

它让用户体验更可预测。

它减少过度支付。

它引入了 ETH 销毁机制。

它让网络使用量和 ETH 供应之间形成直接联系。

这些变化共同影响了 Ethereum 的可用性、经济模型和长期叙事。

## 二十三、总结

EIP-1559 是 Ethereum 手续费机制的一次重要升级。

在旧模型中，用户通过 gas price 参与第一价格拍卖，经常需要猜测费用，容易过度支付，也容易遇到交易延迟。

EIP-1559 引入了 Base Fee、Fee Cap、Tip 和 Base Fee Burn。

Base Fee 是协议根据区块使用率自动调整的基础费用。

Fee Cap 是用户愿意支付的最高上限。

Tip 是给区块生产者的优先费。

Base Fee 会被销毁，从而让网络使用量和 ETH 供应产生联系。

EIP-1559 并不会神奇地大幅降低所有 Gas 费，也不会保证 ETH 永远通缩。它真正解决的是手续费估算、交易包含体验和费用市场结构问题。

如果说传统 gas price 模型是“用户盲猜出价”，那么 EIP-1559 更像是“协议给出基础价格，用户设置最高预算和优先费”。

这让 Ethereum 的费用机制变得更加清晰、可预测，也为后续的扩容和货币政策演进打下了重要基础。
