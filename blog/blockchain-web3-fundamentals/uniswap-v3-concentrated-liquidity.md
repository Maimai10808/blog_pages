# Uniswap v3 详解：集中流动性如何改变 AMM？

Uniswap 是 DeFi 世界里最重要的协议之一。

它本质上是一个运行在以太坊上的去中心化、无需许可的代币交易协议。

在传统交易所里，交易依赖订单簿。买方挂买单，卖方挂卖单，系统撮合成交。

但 Uniswap 使用的是 AMM，也就是自动做市商模型。

用户不需要等待对手盘，而是直接和流动性池交易。

从 v1 到 v2，再到 v3，Uniswap 一直在改进一个核心问题：

```txt
如何让链上交易拥有更好的流动性、更低的滑点和更高的资金效率？
```text

Uniswap v3 的最大变化，就是引入了：

```txt
Concentrated Liquidity
集中流动性
```

这让 LP 不再必须把资金平均铺在从 0 到无限大的整个价格区间，而是可以选择自己想做市的价格范围。

这也是 Uniswap v3 相比 v2 最核心的升级。

---

## 一、先简单回顾 Uniswap v1 和 v2

Uniswap v1 最早在 2018 年上线。

它实现了最基础的 AMM 交易模型，但当时主要支持：

```txt
ETH <-> ERC20
```text

也就是说，很多交易都需要通过 ETH 作为中间资产。

后来，Uniswap v2 在 2020 年上线。

v2 的重要升级是支持：

```txt
ERC20 <-> ERC20
```

这意味着用户可以直接在两个 ERC20 Token 之间建立流动性池。

比如：

```txt
USDC / DAI
ETH / USDC
WBTC / ETH
UNI / ETH
```text

Uniswap v2 很快成为 DeFi Summer 期间最核心的 AMM 协议之一，也成为后来大量 DEX fork 的模板。

v2 的核心模型是经典的常数乘积公式：

```txt
x * y = k
```

LP 把两种资产存入池子，交易者和池子交易，价格由池子中两种资产的比例决定。

---

## 二、Uniswap v2 的问题：资本效率低

Uniswap v2 最大的问题之一是：

```txt
资金利用效率不高。
```text

在 v2 中，LP 提供的流动性会被均匀分布在整个价格区间：

```txt
0 到 ∞
```

这意味着 LP 的资金理论上覆盖了所有可能价格。

听起来很完整，但问题是：

```txt
大部分资产通常只在某个相对有限的价格区间内交易。
```text

例如稳定币池：

```txt
DAI / USDC
```

这两个资产大多数时间都在接近 1 美元附近交易。

可能主要成交范围是：

```txt
0.99 - 1.01
```text

但在 Uniswap v2 中，LP 的资金会被分布到从 0 到无限大的整个价格曲线上。

这就导致大量资金其实很少被用到。

换句话说：

```txt
LP 提供了很多钱，但真正参与交易、产生手续费的只是其中一小部分。
```

这就是 v2 的资本效率问题。

---

## 三、Uniswap v3 的核心：集中流动性

Uniswap v3 通过集中流动性解决这个问题。

在 v3 中，LP 可以自己选择提供流动性的价格区间。

比如 ETH / DAI 当前价格是 2000 美元。

LP 可以选择只在下面这个区间做市：

```txt
1500 - 2500 美元
```text

也可以选择更窄的区间：

```txt
1900 - 2100 美元
```

还可以选择更宽的区间：

```txt
1000 - 4000 美元
```text

这意味着 LP 不再必须把资金平均铺在整个价格曲线上，而是可以把资金集中到更可能发生交易的价格范围内。

可以简单理解为：

```txt
v2：流动性铺满所有价格区间。
v3：流动性集中在 LP 自己选择的价格区间。
```

---

## 四、集中流动性为什么能提高资本效率？

假设 Alice 和 Bob 都想给 ETH / DAI 池子提供流动性。

当前 ETH 价格是 1750 美元。

Alice 使用 v2 风格做市，把资金覆盖整个价格区间。

她投入：

```txt
5000 DAI + 等值 ETH
总价值 10000 美元
```text

Bob 使用 v3 的集中流动性，只在 ETH 价格 1500 到 2500 美元之间提供流动性。

他只投入：

```txt
600 DAI + 等值 ETH
总价值 1200 美元
```

只要 ETH 价格一直在 1500 到 2500 美元之间，Bob 的流动性就会一直处于活跃状态。

在这个区间内，Bob 可能用 1200 美元提供出和 Alice 10000 美元接近的流动性深度。

这意味着 Bob 的资金效率大幅提升。

核心原因是：

```txt
资金不再浪费在极端价格区间，而是集中在真实交易更可能发生的范围。
```text

所以 Uniswap v3 可以让 LP 用更少的资金提供更深的流动性。

对交易者来说，这通常意味着：

```txt
更低滑点
更好成交价格
更接近中心化交易所的交易体验
```

---

## 五、什么是 Active Liquidity？

Uniswap v3 中还有一个很重要的概念：

```txt
Active Liquidity
活跃流动性
```text

LP 提供流动性时，会设置一个价格区间。

只有当市场价格处于这个区间内时，这部分流动性才是活跃的，才能参与交易并赚取手续费。

如果价格跑出这个区间，LP 的流动性就不再参与交易。

也就是说：

```txt
价格在区间内：LP 赚手续费。
价格离开区间：LP 不赚手续费。
```

例如 Bob 给 ETH / DAI 设置的区间是：

```txt
1500 - 2500 美元
```text

如果 ETH 价格在 2000 美元，Bob 的流动性是活跃的。

如果 ETH 涨到 3000 美元，Bob 的流动性就会退出活跃区间。

这时候 Bob 不再赚手续费。

同时，他的仓位也会逐渐变成区间边界对应的单一资产。

所以 v3 LP 不是“放进去不管”就一定好。

LP 需要管理自己的价格区间。

---

## 六、价格跑出区间后会发生什么？

在 v3 中，如果价格离开 LP 设置的价格区间，LP 的资产会完全转向其中一种资产。

举个例子。

假设 LP 在 ETH / USDC 池中设置区间：

```txt
1500 - 2500
```

如果 ETH 价格不断上涨，超过 2500，LP 的仓位可能会全部变成 USDC。

如果 ETH 价格不断下跌，低于 1500，LP 的仓位可能会全部变成 ETH。

此时，这部分流动性不再活跃，也不再赚取交易手续费。

LP 可以选择：

```txt
等待价格回到区间
或者主动调整区间
```text

这也是 v3 和 v2 很大的不同。

v2 更像被动做市。

v3 更像主动管理仓位。

---

## 七、v3 为什么更适合专业 LP？

Uniswap v3 给了 LP 更大的自由度。

但自由度越高，管理难度也越高。

在 v2 中，LP 基本只需要选择交易对，然后按比例提供两种资产。

在 v3 中，LP 还要决定：

```txt
选择哪个价格区间？
区间要宽还是窄？
价格跑出区间后要不要调整？
手续费档位选哪个？
是否要多区间配置？
如何控制无常损失？
```

这让 v3 更像一个专业做市系统。

对于普通用户来说，v3 的 LP 操作难度比 v2 更高。

所以 v3 之后，也出现了很多第三方流动性管理协议，帮助用户自动管理区间、再平衡仓位和复投手续费。

---

## 八、Range Order：像限价单一样做市

集中流动性还带来了一个非常有意思的功能：

```txt
Range Order
区间订单
```text

LP 可以在当前市场价格上方或下方设置一个非常窄的流动性区间。

当市场价格进入这个区间时，LP 的一种资产会沿着曲线逐渐换成另一种资产。

这有点像限价单。

例如 DAI / USDC 当前价格低于 1.001。

LP 可以把 DAI 放到：

```txt
1.001 - 1.002
```

这个很窄的区间里。

当 DAI 价格上涨并穿过这个区间时，LP 的 DAI 会逐渐被换成 USDC。

如果价格完全超过 1.002，LP 的仓位就基本全部变成 USDC。

这就类似于：

```txt
在目标价格附近卖出 DAI，换成 USDC。
```text

但它和传统限价单不同。

因为在 Uniswap v3 中，这个过程是沿着 AMM 曲线逐渐成交的，并且期间还能赚取交易手续费。

不过需要注意：

如果价格穿过区间后，LP 不及时撤出流动性，当价格重新回落时，资产可能又被换回去。

所以 Range Order 需要主动管理。

---

## 九、LP 可以创建自己的价格曲线

在 v3 中，LP 可以在多个价格区间同时提供流动性。

例如在 ETH / DAI 池中，某个 LP 可以这样配置：

```txt
1500 - 2500：投入 2000 美元
2000 - 3000：投入 1000 美元
3500 - 5000：投入 500 美元
```

这些区间可以重叠，也可以不重叠。

这样 LP 就可以组合出自己的做市策略。

某种意义上，v3 允许 LP 自定义自己的流动性分布曲线。

这让 Uniswap v3 不再只是简单的 x \* y = k 被动池子，而是更接近一个可编程的做市系统。

---

## 十、为什么 v3 的 LP Token 是 NFT？

在 Uniswap v2 中，同一个池子的 LP 份额是同质化的。

比如 ETH / USDC 池子的 LP Token 都是一样的 ERC20。

因为所有 LP 的资金都分布在同一个价格范围：

```txt
0 到 ∞
```text

大家只是份额不同，本质上资产结构一样。

但 v3 不一样。

每个 LP 可以设置不同价格区间。

有人设置：

```txt
1500 - 2500
```

有人设置：

```txt
1800 - 2200
```text

有人设置：

```txt
1000 - 5000
```

这些 LP 仓位的风险、收益、资产变化都不同。

所以它们不再是完全同质化的。

因此，Uniswap v3 使用 NFT 来表示 LP 仓位。

也就是说：

```txt
Uniswap v2 LP Token：ERC20
Uniswap v3 LP Position：ERC721 NFT
```text

每一个 v3 LP NFT 都代表一个独立的流动性仓位，包含：

```txt
交易对
价格区间
手续费档位
流动性数量
未领取手续费
```

这也是 v3 的一个重要变化。

---

## 十一、交易手续费不再自动复投

在 Uniswap v2 中，交易手续费会自动留在池子里，间接增加 LP 的池子份额价值。

但在 v3 中，手续费不会自动复投到 LP 的流动性仓位中。

LP 需要主动领取手续费。

如果想自动复投，就需要依赖外围合约或第三方策略协议。

这也让 v3 的 LP 管理更加复杂。

---

## 十二、v3 的多档手续费机制

Uniswap v2 默认手续费是：

```txt
0.3%
```text

但不同资产对的风险并不一样。

例如稳定币之间交易，价格波动很小，LP 承担的无常损失风险较低。

而长尾资产价格波动大，LP 风险更高。

所以 Uniswap v3 引入了多个手续费档位。

常见档位包括：

```txt
0.05%
0.3%
1%
```

不同池子可以选择不同费率。

一般来说：

```txt
0.05%：适合稳定币或高度相关资产
0.3%：适合常规交易对
1%：适合波动较大、风险更高的长尾资产
```text

这样 LP 可以根据资产风险选择合适的费率。

交易者也可以在不同池子之间选择最优路径。

---

## 十三、协议费开关

Uniswap v3 也保留了协议费开关。

也就是说，协议治理可以决定是否从 LP 手续费中抽取一部分作为协议收入。

在 v2 中也有类似机制。

而 v3 的协议费可以按池子单独设置，更加灵活。

不过通常在协议早期或默认情况下，协议费可能不会立即开启。

是否开启取决于 Uniswap Governance。

---

## 十四、Uniswap v3 的预言机改进

Uniswap v2 已经引入了 TWAP 预言机。

TWAP 是 Time-Weighted Average Price，也就是时间加权平均价格。

它可以减少短时间价格操纵对价格读取的影响。

Uniswap v3 对预言机做了进一步改进。

它让协议可以更方便地在链上计算最近一段时间的 TWAP。

同时，维护预言机数据的 gas 成本也比 v2 更低。

这让 Uniswap v3 不只是交易协议，也继续作为 DeFi 生态中重要的链上价格基础设施。

---

## 十五、v3 的 gas 成本如何？

直觉上，v3 功能更多，似乎 gas 会更贵。

但实际设计中，Uniswap v3 在常见 swap 场景里做了很多优化。

简单 swap 的 gas 成本相比 v2 甚至可以更低。

这很重要。

因为 AMM 协议不仅要提高资本效率，也要控制交易成本。

尤其是在以太坊主网上，gas 成本会直接影响用户是否愿意交易。

---

## 十六、Uniswap v3 和 Curve 的竞争

在 v2 时代，Uniswap 对稳定币交易并不占优势。

因为稳定币之间价格非常接近，比如 USDC / DAI，大多数时间都围绕 1 美元附近波动。

Curve 这类稳定币 AMM 专门针对稳定资产设计，能提供更低滑点和更高资本效率。

但 v3 引入集中流动性后，Uniswap 也能让 LP 把资金集中在稳定币的窄价格区间内。

例如：

```txt
0.99 - 1.01
```

这样可以显著提高稳定币池的深度。

因此，v3 在某种程度上同时具备了：

```txt
普通 AMM 的通用性
稳定币 AMM 的高资本效率
```text

这也是为什么很多人认为 v3 是 AMM 领域的重要升级。

---

## 十七、Uniswap v3 和 Layer2

Uniswap v3 最初的重要计划之一，是部署到以太坊主网和 Layer2。

当时重点提到的是 Optimism。

Optimism 是一种 Optimistic Rollup Layer2 扩容方案。

它的目标是提供：

```txt
更快交易
更低手续费
继承以太坊 Layer1 安全性
```

Uniswap 如果部署到 Layer2，会带来明显好处：

```txt
交易成本降低
小额用户更容易参与
LP 调仓成本降低
高频策略更可行
更多用户能使用 DeFi
```text

因为 v3 的 LP 管理比 v2 更主动，可能需要频繁调整价格区间。

如果每次调整都在 Layer1 付高 gas，普通用户很难承受。

所以 v3 和 Layer2 的结合非常关键。

---

## 十八、从 v2 迁移到 v3 是强制的吗？

Uniswap v2 到 v3 的迁移不是强制的。

LP 可以选择继续留在 v2，也可以迁移到 v3。

当年 v1 到 v2 的迁移中，v2 很快超过了 v1 的流动性。

但 v3 的情况更复杂。

因为 v3 的流动性管理方式变化很大。

一些 LP 可能会因为更高资本效率迁移到 v3。

但也有 LP 可能觉得 v2 更简单，更适合被动持有。

所以 v2 和 v3 可以长期共存。

---

## 十九、Uniswap v3 的挑战

Uniswap v3 虽然强大，但也带来了新的问题。

最大的挑战是：

```txt
LP 操作复杂度明显提高。
```

在 v2 中，LP 只需要存入两种资产。

在 v3 中，LP 需要选择价格区间。

如果区间选得太窄：

```txt
资本效率高
但价格容易跑出区间
需要频繁管理
```text

如果区间选得太宽：

```txt
管理简单
但资本效率降低
更接近 v2
```

如果区间选错，LP 可能会：

```txt
赚不到手续费
承担更高无常损失
资产变成不想持有的一边
需要额外 gas 调整仓位
```text

所以 v3 对普通 LP 并不一定更简单。

它更像是把 AMM 变成了一个专业做市工具。

---

## 二十、第三方流动性管理协议的机会

因为 v3 的策略复杂，第三方流动性管理协议就有了很大机会。

这些协议可以帮助 LP：

```txt
自动选择价格区间
自动再平衡
自动复投手续费
根据波动率调整策略
分散配置多个区间
降低手动管理成本
```

这类协议相当于把 v3 的复杂性封装起来，让普通用户也能参与更复杂的做市策略。

从这个角度看，Uniswap v3 不只是一个 DEX 升级，也催生了一个新的 LP 策略管理市场。

---

## 二十一、Uniswap v2 和 v3 核心区别

可以用一张表总结：

| 对比点             | Uniswap v2    | Uniswap v3           |
| ------------------ | ------------- | -------------------- |
| 流动性范围         | 0 到 ∞ 全区间 | LP 自定义价格区间    |
| 核心机制           | 常数乘积 AMM  | 集中流动性 AMM       |
| 资本效率           | 较低          | 大幅提高             |
| LP Token           | ERC20         | ERC721 NFT           |
| 手续费             | 默认 0.3%     | 多档费率             |
| LP 管理难度        | 低            | 高                   |
| 是否自动复投手续费 | 是            | 否                   |
| 适合用户           | 被动 LP       | 主动 / 专业 LP       |
| 稳定币交易效率     | 不如专用 AMM  | 可通过窄区间提高效率 |
| 策略空间           | 较少          | 很大                 |

---

## 二十二、从前端角度理解 Uniswap v3

对 Web3 前端开发者来说，Uniswap v3 比 v2 更复杂。

因为前端不再只是展示一个简单池子份额。

v3 前端需要处理：

```txt
价格区间选择
tick 范围
手续费档位
LP NFT 仓位
当前价格是否在区间内
active liquidity
未领取手续费
增加 / 减少流动性
领取手续费
仓位重平衡
价格区间图表
滑点和价格影响
```text

尤其是 tick 和价格区间，是 v3 前端开发的重要难点。

在 v3 中，价格不是连续随便选的，而是按照 tick 离散化。

LP 选择的价格区间，本质上是选择：

```txt
tickLower
tickUpper
```

前端需要把用户看到的价格区间转换成合约需要的 tick 参数。

这也是 v3 交互比 v2 复杂很多的原因。

## 二十三、面试回答参考

如果面试官问：“Uniswap v3 相比 v2 最大的改进是什么？”

可以这样回答：

Uniswap v3 相比 v2 最大的改进是集中流动性。

在 v2 中，LP 的资金会均匀分布在从 0 到无限大的整个价格区间，这虽然简单，但资本效率很低，因为大多数交易只发生在某个有限价格范围内。

v3 允许 LP 自定义价格区间，把流动性集中到更可能发生交易的价格范围内。这样可以用更少的资金提供更深的流动性，从而提高资本效率、降低交易滑点，并让 LP 在活跃区间内获得更高的手续费收益。

但这也带来了新的复杂性。如果价格跑出 LP 设置的区间，这部分流动性就不再活跃，也无法继续赚取手续费，LP 的资产也会转成其中一种 token。所以 v3 更适合主动管理型 LP 或专业做市策略。

此外，v3 还引入了多档手续费、LP 仓位 NFT、改进版 TWAP 预言机，以及更灵活的 Range Order。整体来看，v3 把 AMM 从简单被动池子升级成了一个更灵活、更资本高效的链上做市系统。

---

## 二十四、总结

Uniswap v3 的核心不是简单升级界面，也不是只提高一点性能。

它真正改变的是 AMM 的流动性分布方式。

v2 的逻辑是：

```txt
所有 LP 的资金铺满整个价格区间。
```text

v3 的逻辑是：

```txt
每个 LP 自己选择价格区间，把资金集中到最有效的位置。
```

这带来了几个关键结果：

```txt
资本效率大幅提高
交易滑点可能降低
LP 可以构建更复杂策略
稳定币交易竞争力增强
LP 仓位变成 NFT
做市难度明显提高
第三方策略管理协议变得重要
```text

所以 Uniswap v3 可以理解为：

```txt
从被动 AMM 到主动区间做市的转变。
```

它让 AMM 不再只是简单的资金池，而更像一个可编程、可组合、可策略化的链上做市基础设施。

对于 Web3 前端开发者来说，理解 v3 的重点不只是“集中流动性”这个词，而是要理解：

```txt
为什么 v2 资本效率低？
v3 如何通过价格区间提高效率？
价格跑出区间后会发生什么？
为什么 LP Token 变成 NFT？
多费率和 Range Order 解决了什么问题？
前端为什么要处理 tick、区间、仓位和手续费？
```

能把这些讲清楚，才算真正理解 Uniswap v3。
