# 从零搭建企业级 Mono Repo 工程：前端高薪必备技能

在前端开发中，很多同学可能只熟悉小项目开发，但当你进入大型项目时，你会发现几乎所有企业都在用 Mono Repo（单仓库管理） 来组织代码。它不仅是一种代码组织方式，更是现代前端工程能力的分水岭。如果你不会 Mono Repo，想拿高薪项目的入场券几乎不可能。

本文将带你从零开始理解并搭建一个企业级 Mono Repo 工程，帮助你掌握大型项目的工程化能力。

---

## 一、为什么要用 Mono Repo？

在一条业务线里，往往涉及多个项目：

- 前端：Web 端、移动端
- 后端：微服务、中间层
- 基建：组件库、函数库、SDK、命令行工具
- 低码开发工具等

如果每个项目独立建仓（Multi Repo），会产生一系列问题：

1. 依赖难管理：组件库、函数库、前端项目互相依赖，版本更新难以同步。
2. 配置不统一：每个仓库都需要单独配置构建、类型检查、打包规则。
3. 跨项目协作困难：前端、后端、公共库开发团队无法高效统一管理。

而 Mono Repo 的核心思想是：将相关联的包放到同一个仓库，便于统一管理。

核心判断逻辑：包之间的关联是强还是弱？

- 关联强 → 放在同一个仓库
- 关联弱 → 独立仓库（Multi Repo）

---

## 二、Mono Repo vs Multi Repo

| 特性 | Multi Repo（多仓） | Mono Repo（单仓） |
| --- | --- | --- |
| 仓库数量 | 每个包一个仓库 | 所有相关包在同一仓库 |
| 适用场景 | 包之间独立，依赖弱 | 包之间强关联，共同完成业务目标 |
| 维护成本 | 高，跨仓库管理麻烦 | 低，可统一版本、统一工具链 |

总结一句话：本质区别就是“一个包一个仓库”还是“多个包一个仓库”，其他差异都是衍生问题。

---

## 三、Mono Repo 技术选型

实现 Mono Repo 有多种工具选择：

- 轻量级：PNPM（推荐）、NPM
- 集成度高：Lerna、Turborepo、Rush（适合复杂企业级发布流程）

我们推荐使用 PNPM：

- 轻量、灵活
- 支持工作区（Workspace）
- 流行于开源库（如 Vue 源码）和第三方项目
- 学会之后可无缝迁移到其他工具

---

## 四、Mono Repo 目录结构示例

```txt
do1-mono-repo/
├─ apps/
│  ├─ frontend/ # 前端项目
│  └─ backend/  # 后端项目
├─ packages/
│  ├─ components/ # 组件库
│  ├─ utils/      # 函数库
│  └─ cli-tools/  # 命令行工具
├─ package.json
└─ pnpm-workspace.yaml
```

- apps/：业务型子包
- packages/：公共基建子包
- 每个子包可单独开发、测试、打包
- 根目录统一管理依赖、TypeScript 配置、Lint 规则

## 五、关键工程管理点（1235）

在学习 Mono Repo 时，每个知识点可以从五个层面理解，但重点关注 1、2、3、5：

1. 问题驱动：当前面临什么问题？

## 六、统一工程化管理

### 1. 环境版本锁定

- Node、NPM、PNPM 版本统一
- 根目录配置 engines 或 .npmrc
- 确保所有子包环境一致，避免低版本兼容问题

### 2. TypeScript 配置

- 根目录统一 TS 配置（tsconfig.json）
- 子包可继承根配置并覆盖特定环境（Node / Browser）

### 3. 代码风格和质量检查

- Prettier：格式统一
- ESLint：代码质量
- Spell Checker：拼写检查
- 配置统一在根目录，结合 PNPM Workspace 管理子包

### 4. Git 提交规范

- 使用 commitlint + husky + lint-staged
- 提交前自动检查格式、代码质量
- 保证团队协作和提交标准化

---

## 七、Mono Repo 工程管理的优势

1. 依赖同步简单：组件库、工具库统一管理
2. 统一构建与类型检查：所有子包共享 TS、Lint、Prettier 配置
3. 自动化约束：提交、测试、发布流程标准化
4. 提高协作效率：前端、后端、基建团队在同一仓库协作
5. 易于扩展：新增子包仅需更新 workspace 配置

---

## 八、总结

- Mono Repo 是前端高薪工程能力的分水岭：掌握它，才能进入大型项目开发
- 核心判断：包之间是否强关联 → 决定合并或分仓
- 技术实现可选工具众多，推荐 PNPM + TypeScript + Prettier + ESLint + commitlint
- 统一配置与规范化管理是核心，技术实现细节可查文档或 AI
