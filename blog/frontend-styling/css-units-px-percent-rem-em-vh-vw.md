# CSS 单位怎么选？一次讲清 px、%、rem、em、vh、vw 的使用场景

在网页设计和前端开发中，我们经常会遇到这些单位：

```text
px、%、rem、em、vh、vw
```

如果你使用 Elementor、Webflow、WordPress，或者直接写 CSS，这些单位都会经常出现。它们不是 Elementor 独有的单位，而是 CSS 中通用的尺寸单位。

很多新手一开始最熟悉的是 `px`，因为它最直观。但真正做响应式网站时，如果所有尺寸都用像素，很快就会发现页面在不同屏幕上很难适配。

这篇文章会系统讲清楚这些单位分别是什么意思、适合用在哪里，以及在实际项目中应该怎么选择。

---

## 一、px：最直观，但不要滥用

`px` 是 pixel，也就是像素。

它是一个**绝对单位**。简单理解就是：

```text
1px 就是 1px
```

如果你把字体大小设置成：

```css
font-size: 20px;
```

那么无论用户是在电脑屏幕、平板还是手机上看，这个字体大小都会是 20px。

这听起来很稳定，也确实很容易控制细节。但问题是，现在设备尺寸太多了。电脑、平板、手机、折叠屏、超宽屏，每一种屏幕的宽度和分辨率都不一样。

所以传统的“像素级还原”思路已经越来越不适合现代响应式网页设计了。

如果你试图让页面在所有设备上都完全一样，最后只会非常痛苦。

### px 适合用在哪里？

虽然不建议所有地方都用 px，但 px 仍然很有用。

比较适合使用 px 的地方包括：

```text
图标尺寸
图片固定尺寸
细节级 margin
细节级 padding
负 margin
网站最大宽度
```

比如图标一般希望保持稳定大小：

```css
.icon {
  width: 24px;
  height: 24px;
}
```

再比如网站整体内容区域的最大宽度，也经常用 px 控制：

```css
.container {
  max-width: 1200px;
}
```

这样可以避免大屏幕下内容无限拉伸，保持页面阅读体验稳定。

另外，如果你需要使用负 margin，px 也比较好控制。因为负间距本身就容易出问题，用 px 会更直观。

### px 的使用建议

可以这样理解：

```text
需要绝对稳定的细节，用 px。
需要响应式变化的布局，不要优先用 px。
```

---

## 二、%：基于父元素的相对单位

百分比 `%` 是响应式布局中非常重要的单位。

它的核心特点是：

```text
百分比基于父元素计算。
```

比如一个子元素写：

```css
padding-left: 10%;
padding-right: 10%;
```

这个 `10%` 不是基于整个屏幕，而是基于它的父元素宽度。

如果父容器宽度是 1000px，那么：

```text
10% = 100px
```

如果父容器宽度是 500px，那么：

```text
10% = 50px
```

这就是百分比的关键：**它会随着父元素尺寸变化而变化。**

---

## 三、什么是父元素？

在 HTML 结构里，一个元素包着另一个元素，那么外面的就是父元素，里面的就是子元素。

比如：

```html
<div class="parent">
  <div class="child"></div>
</div>
```

这里 `.parent` 是父元素，`.child` 是子元素。

在 Elementor 里也一样：

```text
Container 是父元素
里面的 Heading、Image、Text Editor、Button 是子元素
```

如果一个 Container 里面再放一个 Container，那么外层 Container 就是内层 Container 的父元素。

所以当你给子元素设置百分比 padding 或 margin 时，它会根据父元素的尺寸来计算。

---

## 四、为什么 padding 很适合用 %

百分比特别适合做响应式 padding。

比如一个大容器设置：

```css
padding-left: 5%;
padding-right: 5%;
```

当用户屏幕很宽时，左右留白会变大；当用户屏幕较窄时，左右留白会变小。

这非常符合响应式设计的逻辑。

大屏幕有更多空间，就可以留出更多呼吸感。
小屏幕空间有限，就减少留白，避免内容被挤得太窄。

比如：

```text
桌面端：左右 padding 5%
平板端：左右 padding 5%
移动端：左右 padding 5%
```

这样同一套规则就可以适配不同屏幕。

### 一个常见的 spacing 思路

在实际网站设计中，可以这样设置大容器的 padding：

```text
桌面端：上下 10%，左右 5%
平板端：上下 15%，左右 5%
移动端：上下 20%，左右 5%
```

为什么移动端上下 padding 反而更大？

因为移动端内容通常是单列排列，元素纵向堆叠，如果上下空间太小，页面会显得很挤。适当增加纵向空间，可以提升阅读体验。

### % 的使用建议

```text
大容器左右 padding：非常适合用 %
响应式留白：适合用 %
元素之间的间距：也可以用 %
```

但要记住：

```text
% 不是基于屏幕，而是基于父元素。
```

这一点非常重要。

---

## 五、vh 和 vw：基于视口的单位

`vh` 和 `vw` 是基于 viewport，也就是视口的单位。

视口可以理解为：

```text
用户当前能看到网页内容的区域。
```

注意，视口不一定等于整个屏幕。浏览器地址栏、书签栏、系统栏等，都不属于网页视口。

### vh 是什么？

`vh` 是 viewport height，表示视口高度。

```text
100vh = 视口高度的 100%
50vh = 视口高度的 50%
```

如果一个区域设置：

```css
min-height: 100vh;
```

意思就是这个区域至少占满整个视口高度。

这常用于 Hero Section，也就是网站首屏大图区域。

比如：

```css
.hero {
  min-height: 100vh;
}
```

这样用户一打开网站，Hero 区域就会占满整个屏幕高度。

### vw 是什么？

`vw` 是 viewport width，表示视口宽度。

```text
100vw = 视口宽度的 100%
80vw = 视口宽度的 80%
```

比如：

```css
.container {
  width: 80vw;
}
```

意思是容器宽度始终是视口宽度的 80%。

---

## 六、% 和 vw / vh 的区别

很多人容易混淆 `%` 和 `vw / vh`。

区别其实很简单：

```text
%：基于父元素
vw / vh：基于视口
```

比如：

```css
width: 80%;
```

这个 80% 是父元素宽度的 80%。

而：

```css
width: 80vw;
```

这个 80vw 是视口宽度的 80%。

如果父元素不是全屏宽度，那么两者结果会完全不同。

---

## 七、vh 和 vw 适合用在哪里？

`vh` 和 `vw` 适合用来控制和视口强相关的区域。

常见场景有：

```text
首屏 Hero 区域
全屏 Banner
全屏弹窗
某个区域至少占据半屏高度
横向响应式宽度
```

比如：

```css
.hero {
  min-height: 100vh;
}
```

或者：

```css
.section {
  min-height: 50vh;
}
```

如果你想让一个区域始终占据用户可见高度的一半，就可以用 `50vh`。

不过在普通内容布局中，不一定要大量使用 `vh` 和 `vw`。很多时候，用容器宽度、padding、max-width 就足够了。

### vh / vw 的使用建议

```text
想让某个区域和视口高度/宽度绑定时，用 vh / vw。
普通内容布局，不必强行使用 vh / vw。
```

---

## 八、rem：最推荐用于字体大小

`rem` 是 root em 的意思。

它基于根元素，也就是 HTML 的字体大小。

浏览器默认情况下，HTML 的字体大小通常是：

```text
16px
```

所以默认情况下：

```text
1rem = 16px
2rem = 32px
0.5rem = 8px
```

如果你把根字体大小改成 10px，那么：

```text
1rem = 10px
2rem = 20px
0.5rem = 5px
```

但一般来说，没有必要改 HTML 的默认字体大小。保持默认的 16px 就可以。

---

## 九、为什么字体建议用 rem，而不是 px？

字体大小用 `rem` 有两个主要好处。

### 1. 更适合可访问性

如果用户在浏览器或系统里调整了默认字体大小，`rem` 会更容易跟随这些偏好变化。

而 `px` 更容易把字号固定死。

对于普通用户来说，这个差异可能不明显。但对于视力较弱、需要放大字体的用户来说，这很重要。

所以从可访问性角度，`rem` 通常比 `px` 更友好。

### 2. 更容易管理比例

用 `rem` 可以更容易理解不同字号之间的比例关系。

比如：

```text
1rem = 正文字号
2rem = 正文字号的 2 倍
3rem = 正文字号的 3 倍
```

这比一直计算像素更舒服。

例如：

```css
body {
  font-size: 1rem;
}

h1 {
  font-size: 3rem;
}

h2 {
  font-size: 2rem;
}
```

你可以很直观地知道：

```text
h1 是正文的 3 倍
h2 是正文的 2 倍
```

如果全部用 px，就需要不断换算：

```text
16px、24px、32px、48px、64px
```

不是不能用，但维护起来更容易乱。

---

## 十、rem 适合用在哪里？

`rem` 最推荐用于：

```text
字体大小
部分 padding
部分 margin
元素间距 gap
```

例如：

```css
body {
  font-size: 1rem;
}

h1 {
  font-size: 4rem;
}

.card {
  padding: 2rem;
  gap: 1rem;
}
```

如果你想让整个网站的文字和间距有统一比例，`rem` 会非常好用。

---

## 十一、em：基于当前元素或父元素字体大小

`em` 比 `rem` 更容易让人混乱。

简单来说：

```text
rem 基于 HTML 根字体大小
em 基于当前元素或父元素的字体大小
```

在很多情况下，`em` 会受到父级字体大小影响，所以层级一多就容易变复杂。

因此，不建议大量使用 `em` 来设置字体大小。否则你可能很难判断最后实际渲染出来到底是多少 px。

但 `em` 在两个场景下非常好用：

```text
line-height
button padding
```

---

## 十二、为什么 line-height 适合用 em？

在排版设计中，一个常见规则是：

```text
行高约等于字体大小的 1.5 倍
```

也就是 150%。

如果字体大小是：

```css
font-size: 1rem;
```

那么行高可以设置成：

```css
line-height: 1.5em;
```

这里的 `1.5em` 可以理解成：

```text
当前字体大小的 1.5 倍
```

如果字体变大，行高自动跟着变大。
如果字体变小，行高自动跟着变小。

这比你手动计算像素方便很多。

比如：

```css
p {
  font-size: 1rem;
  line-height: 1.5em;
}
```

如果你之后把字体改成：

```css
font-size: 1.25rem;
```

行高仍然会自动保持 1.5 倍比例。

如果用 px，你就需要重新计算行高。

---

## 十三、line-height 用 em 的好处

假设一个标题：

```css
h1 {
  font-size: 4rem;
  line-height: 1.2em;
}
```

这里 `1.2em` 的意思就是：

```text
行高 = 当前字体大小的 1.2 倍
```

如果你把 h1 改成：

```css
font-size: 3rem;
```

行高仍然保持 1.2 倍。

这就非常方便。

所以建议：

```text
font-size 用 rem
line-height 用 em
```

例如：

```css
h1 {
  font-size: 4rem;
  line-height: 1.15em;
}

p {
  font-size: 1rem;
  line-height: 1.5em;
}
```

这是一种很稳定的排版方式。

---

## 十四、em 也适合按钮 padding

按钮是另一个适合使用 `em` 的地方。

原因是按钮的 padding 通常应该随着文字大小一起变化。

比如：

```css
.button {
  font-size: 1rem;
  padding: 1em 1.5em;
}
```

这里的 padding 会基于按钮自己的字体大小计算。

如果按钮字体变大，按钮内部留白也会跟着变大。
如果按钮字体变小，按钮内部留白也会跟着变小。

这样可以保证不同大小按钮的比例一致。

对比一下：

### 用 em

```css
.button {
  font-size: 1rem;
  padding: 1em 1.5em;
}
```

按钮会随着字号自然变大。

### 用 px

```css
.button {
  font-size: 2rem;
  padding: 15px;
}
```

字体变大了，但 padding 还是固定 15px，按钮可能会显得很挤。

所以按钮 padding 使用 `em`，可以让组件更灵活、更一致。

---

## 十五、em 不建议滥用

虽然 `em` 很强，但不建议所有地方都用。

因为它受当前元素和父级字体大小影响，嵌套多了以后，计算会比较复杂。

例如：

```css
.parent {
  font-size: 20px;
}

.child {
  font-size: 2em;
}
```

这里 `.child` 的字体大小就是 40px。

如果再嵌套一层继续用 `em`，尺寸可能会被不断放大或缩小。

所以实践中可以这样用：

```text
字体大小：优先 rem
行高：推荐 em
按钮 padding：推荐 em
其他场景：谨慎使用 em
```

---

## 十六、不同单位的推荐使用场景

下面按单位总结一下。

### px

适合：

```text
图标大小
图片固定尺寸
边框
细节级 margin / padding
负 margin
网站最大宽度
```

不适合：

```text
大面积响应式布局
所有字体大小
所有间距
```

---

### %

适合：

```text
容器 padding
响应式左右留白
父元素内的相对宽度
元素间距
```

注意：

```text
% 基于父元素，不是基于屏幕。
```

---

### vh / vw

适合：

```text
全屏首屏
Hero Section
全屏弹窗
固定视口比例区域
视口宽度相关布局
```

注意：

```text
vh 基于视口高度
vw 基于视口宽度
不是基于父元素
```

---

### rem

适合：

```text
字体大小
全局排版系统
部分 padding
部分 margin
gap
```

推荐：

```css
body {
  font-size: 1rem;
}
```

---

### em

适合：

```text
line-height
按钮 padding
需要跟随当前字体大小变化的局部尺寸
```

推荐：

```css
p {
  font-size: 1rem;
  line-height: 1.5em;
}

.button {
  padding: 1em 1.5em;
}
```

---

## 十七、一个比较实用的工作流

如果你不知道怎么开始，可以使用这套简单规则：

```text
字体大小：用 rem
正文行高：用 em
标题行高：用 em
按钮 padding：用 em
大容器左右 padding：用 %
大容器上下 padding：用 %
网站最大宽度：用 px
图标大小：用 px
需要全屏高度：用 vh
需要基于视口宽度：用 vw
```

比如一个页面可以这样设计：

```css
.container {
  max-width: 1200px;
  padding-left: 5%;
  padding-right: 5%;
}

.section {
  padding-top: 10%;
  padding-bottom: 10%;
}

.hero {
  min-height: 100vh;
}

h1 {
  font-size: 4rem;
  line-height: 1.15em;
}

p {
  font-size: 1rem;
  line-height: 1.5em;
}

.button {
  font-size: 1rem;
  padding: 1em 1.5em;
}

.icon {
  width: 24px;
  height: 24px;
}
```

这套写法既能保持响应式，又不会让尺寸失控。

---

## 十八、不要追求完全 Pixel Perfect

最后要强调一点：

现代网页设计里，完全 Pixel Perfect 已经越来越不现实。

因为用户设备太多了：

```text
手机
平板
笔记本
台式机
超宽屏
高分屏
浏览器缩放
系统字体设置
```

如果你要求页面在所有设备上都一模一样，开发和维护成本会非常高。

更合理的目标是：

```text
保持比例一致
保持视觉层级清晰
保持阅读体验舒服
保持响应式自然
```

也就是说，不是让所有设备看起来完全一样，而是让所有设备看起来都合理。

---

## 总结

CSS 单位没有绝对唯一的正确答案，不同项目和不同设计系统会有不同习惯。但对于大多数响应式网站，可以遵循这套通用思路：

```text
px：适合固定尺寸和精细控制
%：适合基于父容器的响应式留白
vh / vw：适合基于视口的全屏或比例布局
rem：适合字体大小和统一比例系统
em：适合行高和按钮 padding
```

最推荐的组合是：

```text
字体大小用 rem
行高用 em
按钮 padding 用 em
容器 padding 用 %
网站最大宽度用 px
首屏高度用 vh
```

掌握这些单位后，你在做响应式设计时会更轻松，也更容易建立一套稳定的设计和开发工作流。
